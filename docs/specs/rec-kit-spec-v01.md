## 0. 目的と範囲

- 新台ごとに器（rec本体）を改造せず、「機種セット＝部品の一覧」を足すだけで記録ツールとして使えるようにする。
- 部品は運営が解析から用意し、ユーザーはオン／オフ・表示名・並びを自分用に変える。解析にない項目はユーザーが自由ボタンを作る。
- v0 は「試作として実戦で使える最小版」。配布の仕組み・CSV・状態を変える部品は入れない（§7）。

## 1. 箱の構成

| 項目 | 内容 |
|---|---|
| コピー元 | 本線 rec98 `tools/rec/index.html`（かのかり箱ではない。stocks 等の専用拡張を持ち込まないため） |

## 2. データの持ち方

### 2-A. 機種セット（運営が作る・読み取り専用）

```json
{ "schema":"rec-kit", "kitVer":"1.0",
  "machineId":"kanokari", "machineName":"彼女、お借りします",
  "parts":[
    { "key":"eye_normal", "label":"アイキャッチ（通常時）", "tags":["設定示唆"],
      "options":[ {"key":"white","label":"白"}, {"key":"blue4","label":"青・4人"} ] },
    { "key":"stage", "label":"ステージ", "tags":["モード示唆"],
      "options":[ {"key":"room","label":"部屋と彼女"} ] },
    { "key":"zencho", "label":"前兆開始", "tags":["当選期待度"] }
  ] }
```

- `key` は内部キー（不変）、`label` は表示名（可変）。`data/machines/my_juggler_v.json` の `ui.count_buttons` と同じ語彙。
- `options` 無しの部品は「押すだけで1行記録」。有りの部品はシートで1つ選んで記録。
- v0 の部品は **`set:` を持たない**（状態を変えない）。これにより applyHints / hintsFromEv の機種固有部分を迂回する。

### 2-B. ユーザー設定（`S.settings.kits` を新設）

```json
"kits": {
  "kanokari": {
    "kitVer": "1.0",
    "off":    ["eye_zen"],
    "rename": { "eye_normal": "アイキャッチ" },
    "order":  ["stage","eye_normal","zencho"],
    "custom": [ { "key":"u_k3f9x", "label":"右上のランプ", "tags":["設定示唆"] } ]
  }
}
```

- 自由ボタンのキーは `u_` 前置＋ランダム5字。配布セットと衝突させない。
- `off` は**表示しないだけ**。記録済みの行には触らない（manageTags の削除挙動を流用しない）。
- `order` に無い部品（セット更新で増えた分）は末尾に並べる。既定値補完は load 時に1回。

### 2-C. 記録（`events[]` に2キー追加）

```json
{ "type":"extra", "text":"アイキャッチ：白", "extra":"アイキャッチ", "sel":{"eye_normal":"白"},
  "partKey":"eye_normal", "optKey":{"eye_normal":"white"}, "kitVer":"1.0",
  "tags":["設定示唆"], "at":"…", "realG":0, "lcdG":0, "c3":0, "mode":"normal", "op":"…" }
```

- `type:"extra"` のまま（LOG_KIND・hintsFromEv の汎用分岐・showHintSummary が無改修で効く）。
- `text` / `extra` / `sel` は**押した時点の表示名で確定し、以後書き換えない**。表示名の変更は表示時の差し替えのみ。
- `kitVer` を行に写す（後でセットが更新されたとき、どの版の部品で押したかを追うため）。

## 3. 基本タグ（夢爽確定・7つ）

```
DEF_TAGS = ["設定示唆","モード示唆","高確示唆","G数示唆","当選期待度","当選契機","その他"]
```

- 現行の「当選示唆」「天井・規定G」は使わない（新しい箱は保存先が別なので移行不要）。
- タグの追加・名前変更・削除は既存 manageTags をそのまま使う。削除時の「既存行から外す」挙動は据え置き（確認ダイアログに件数が出ることを確認する）。
- 「当選期待度」＝当たる前の手がかり、「当選契機」＝何で当たったかの事実。説明文をタグ管理画面に1行ずつ添える。

## 4. 実戦画面（390×844 基準）

- ヘッダ／カウンター3つ／お金／−1000・入金・再プレイ／バッジ行は本線のまま。
- グリッドは **3行×3列＝9枠**。配置：
  - 枠1〜7：オンの部品を `order` 順に上位7つ
  - 枠8：「当選」（既存 hit）
  - 枠9：「メモ」（既存 openMemo）。ただし部品が8個以上のときは枠9を**「部品をもっと」**にし、残りをシートで一覧表示（メモはシート内の先頭に置く）
- グリッド行数は増やさない（1行追加で下端が約710pxになり iPhone Safari で切れる）。
- グリッドは **キー参照で動的生成**する。`extra:0` 形式の添字参照（1066行）は使わない。
- ボタン表記は表示名（rename 適用後）。長い表示名は2行まで、超過は末尾省略。

## 5. 設定画面「記録ボタンの設定」

入口：ヘッダ「≡」メニューに追加（「タグの管理」の隣）。シートは内部スクロール（`.sheet .pane{max-height:72dvh}` 据え置き）。

| 機能 | 動き |
|---|---|
| 一覧 | セットの部品＋自由ボタンを `order` 順に表示。各行に トグル／表示名／タグ／▲▼ |
| オン／オフ | トグル。オフは非表示のみ |
| 表示名の変更 | 行タップ→askText。空なら元の label に戻る。保存は `rename` のみ |
| 並び替え | ▲▼ボタン（ドラッグは positionSheet のスワイプと干渉するため不採用） |
| 自由ボタン追加 | 「＋ボタンを追加」→ 名前（必須）＋タグ（tagPicker・複数可）→ 追加 |
| 自由ボタン編集・削除 | 行タップ→名前・タグ変更／削除。削除は**設定から消すだけ**で記録は残す。確認ダイアログあり |
| 既定に戻す | 「このセットを既定に戻す」（off/rename/order を空に。custom は残す）。確認ダイアログあり |

「ありえない入力」の排除：名前が空／既存と同名の自由ボタンは追加不可。タグ未選択は「その他」を自動付与。

## 6. 容量対策（最小版で必須）

- 別KEY（§1）で本線と容量を食い合わない。
- 設定画面の下に「終了した台を書き出して消す」導線：終了済みセッションを JSON 書き出し（dlJson 流用）→成功後に削除の確認→削除。書き出し前の削除はできない。
- stripSnaps は既存のまま。

## 7. v0 に入れないもの

セットの外部配布（fetch／JSON取り込み）、CSV出力、byState（状態別の部品）、`set:` を持つ部品、設定判別チェッカーへの送信（toChecker）、複数機種セットの切り替え。
→ ただし `kits` を machineId でキーにしておくことで、複数機種・配布は後から足せる形にする。

## 8. かのかりセット（v0 同梱分）

- 正本は `docs/specs/kanokari-def-v20.js`。着手前に `tools/rec-kanokari/index.html` の同梱定義と一致することを確認し、ずれていれば報告して止める。
- ミコトがそこから**名前とタグの一覧だけ**を抽出して `parts` を作る。状態遷移・ストック・攻略人数などの器拡張は持ち込まない。
- 抽出対象の目安：アイキャッチ（通常時／海と彼女突入時など区間が違うものは別部品）、ステージ、セリフ、ボイス、前兆開始、CZ当選、REG。
- タグの初期値：アイキャッチ＝設定示唆または当選期待度（定義の意味に従う）、ステージ＝モード示唆、前兆・CZ＝当選期待度、当選の契機＝当選契機。迷う部品は「その他」にして報告に挙げる。
- 抽出結果（部品名・選択肢・タグの一覧）は報告に全文を載せ、シオンが解析と照合する。
