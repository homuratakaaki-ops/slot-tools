## 1. 夢爽の要望

1. 通常時に「レア役」ボタンを1つ置き、押すと出るシートに次の6つを入れる：**弱チェリー・強チェリー・スイカ／チャンス目・赫眼リプ・確定チェリー**（チャンス目はA・Bに分けない）
2. チェリーとスイカは絵文字で表示する
3. 色分けは必須：チェリー系（弱・強・確定）＝赤、スイカ＝緑、チャンス目＝紫、赫眼リプ＝青
4. スイカからの液晶ゲーム数加算を「スイカ加算」として置く。加算量は 10／100／600（MAX）の3種類。仕組みは既存の液晶G加算とほぼ同じ
5. 「レア役」と「スイカ加算」は通常時の画面の上（TOP）に置く。スイカがレア役とスイカ加算の2か所に出るのはこのままでよい
6. 「CZスルー+1」ボタンは外す。CZスルーは、レミニセンス・大喰いの利世の失敗で自動的に+1される（第1弾で実装済みの `counter3.incOnCzFail`。今回は変えない）
7. 代わりに「前兆」ボタンを置く：
   - 通常時に押す → 「前兆」「前兆ステージ」の2つから選ぶ
   - 「前兆」を選ぶ → 前兆という状態になり、ボタンの表示が「前兆中」に変わる
   - 「前兆中」を押す → 「前兆ステージいかず」「前兆ステージ」の2つから選ぶ
     - 前兆ステージいかず → 前兆の状態が解除され、ボタンは「前兆」に戻る
     - 前兆ステージ → 前兆ステージの状態に移り、ボタンは「前兆ステージ」になる
   - 前兆ステージ中にCZ・ATが当選したら、状態は解除される（既存どおり）
   - 「前兆ステージ」ボタンを押すと、**確認のシートを出さずに一発で**前兆ステージが解除され、通常時に戻る
8. 通常時の並び：1段目「レア役・スイカ加算・当選」、2段目「示唆・前兆・メモ」

## 2. 定義の変更（`MACHINES.tokyoghoul`）

```js
  rares:[
    {key:"cherryW",label:"弱🍒",tone:"red"},
    {key:"cherryS",label:"強🍒",tone:"red"},
    {key:"melon",label:"🍉",tone:"green"},
    {key:"chance",label:"チャンス目",tone:"purple"},
    {key:"kakugan",label:"赫眼リプ",tone:"blue"},
    {key:"cherryK",label:"確定🍒",tone:"red"}
  ],
  lcdAdd:{label:"スイカ加算",steps:[10,100,600],stepLabels:{600:"+600（MAX）"},chars:null,tone:"green"},
  rareCounts:"never",
  zenchou:{stages:["前兆","前兆ステージ"],stageIndex:1,outGroups:[],
    buttonLabels:{idle:"前兆",active:["前兆中","前兆ステージ"]},   // Z1
    cutLabel:"前兆ステージいかず",                                // Z2
    stageOneTapEnd:true},                                         // Z3
  grids:{
    normal:[
      ["rare","lcdAdd","hit"],
      ["extra:0","zenchou","memo"]
    ],
    cz:[["hitEnd","memo"]],
    at:[["hitEnd","memo"]]
  }
```

- レア役は弱／強を1つのボタンで切り替える方式（`strong`）は使わない。6つとも独立した回数（`n`）を持つ
- 第1弾の `zenchou:null`・`lcdAdd:null`・`rares:[]`・`rareCounts:false`・`grids` は、上の内容で置き換える（重複させない）
- 「レア役」ボタンは既存の `rare`（`openRare()`）を使う。強弱の切り替えは出ない（`strong` を持つ役が無いため。既存動作）
- シートの並びは定義の順（弱🍒・強🍒・🍉／チャンス目・赫眼リプ・確定🍒）。1行3つで2段になること
- 回数はシートの「回数を直す」欄で見せる。上の回数一覧（`#rareCounts`）は東京喰種では出さない（`rareCounts:"never"`）
- `hitTriggers` の「レア役」はそのまま（どのレア役かはログの直前行で分かる）

## 3. 共通部分の追加（定義に指定があるときだけ効く）

### R1 色（`tone`）
- CSS を足す（既存の `tone-p`／`tone-c`／`tone-d` は変えない）：
  - `tone-red`：赤系（既存 `tone-d` と同じ色味）
  - `tone-green`：緑系（`var(--ok)` を基準）
  - `tone-purple`：紫系（既存 `tone-p` と同じ色味）
  - `tone-blue`：青系（既存 `tone-c` と同じ色味）
  - 対象：グリッドのボタン（`.grow button.tone-*`。`.pri` より優先されること）、レア役シートの選択肢（`.opts button.tone-*`）
- `openRare()`：「引いた役」の選択肢と「回数を直す」の選択肢に、そのレア役の `tone` があれば `tone-<値>` を付ける（6つとも色分け必須）
- `makeGridButton()`：`rare:キー` のボタン（今回は使わないが同じ規則）と `lcdAdd` のボタンに、`tone` があれば `tone-<値>` を付ける。「レア役」ボタン自体は今の見た目のまま
- 文字色は、背景が暗くても読める明るさにする（390px・暗い画面で確認）

### R2 加算量の表示名（`lcdAdd.stepLabels`）
- `openLcdAdd()`：`stepLabels[n]` があればそれを、無ければ今の「+n」をボタンに出す
- 記録の値は数値のまま（`add:600`）。ログの本文は今と同じ形（「スイカ加算 +600」）

### R3 回数一覧を出さない（`rareCounts:"never"`）
- `renderRare()`：`d.rareCounts==="never"` なら、状態にかかわらず `#rareCounts` を隠す。`false` の今の扱い（AT中だけ出す）は変えない

---

### Z1 前兆ボタンの表示名（`zenchou.buttonLabels`）
- `zenchouLabel()`：`buttonLabels` があれば、通常時は `idle`、段階中は `active[今の段階]` を返す。無ければ今の処理（既存機種は変えない）

### Z2 「発展せず」の文言（`zenchou.cutLabel`）
- `openZenchou()`：前兆ステージでない段階の「終わる」ボタンの文言に `cutLabel` を使う。ログの本文も同じ文言（「前兆ステージいかず」）。無ければ今の「◯◯ 発展せず」
- 通常時に押したときのシートは今のまま（「前兆」「前兆ステージ」の2つが出る）。前兆中に押したときは「前兆ステージ」と「前兆ステージいかず」の2つが出ること

### Z3 前兆ステージを一発で終える（`zenchou.stageOneTapEnd`）
- 前兆ステージ中に前兆ボタン（グリッド）または状態バッジを押したら、シートを出さずにその場で終える：`mark()` → `zenchou` を通常へ → ステージ表示を戻す → `applyStageEnd()` → ログ「前兆ステージ 終了」（1操作）
- 前兆ステージ中のCZ・AT当選は今のまま（`startHit()` が状態を解除し、当選行に「前兆ステージから」が付く）
- 指定がない機種は今のまま（シートで「失敗」を選び、終了画面などを入れる）

## 4. 取り消し

- レア役・スイカ加算は既存の処理（`mark()` による状態の写し、`lcdAdd` の加算分を戻す処理）でそのまま戻る。追加の処理は不要
- 確認：レア役を押して取り消す → 回数が1減る。スイカ加算 +600 を取り消す → 液晶Gが600戻る
- 前兆の出入り（前兆・前兆ステージ・前兆ステージいかず・一発終了）も既存の状態の写しで1操作ずつ戻る（`zenchou` は既に `SNAP_KEYS` にある）
