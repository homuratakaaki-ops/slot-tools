## 0. 要するに

- 記録ツール（rec）は「打っている間に押す」道具、稼働日誌は「全部の記録を貯めて振り返る」場所
- 保存は IndexedDB（端末の中の大きい保存領域）。rec の 5MB 問題は、終わった台をノートへ移すことで片付ける
- 画面は3つ：**今日を見る → 日・台を振り返る → 収支を比べる**
- ノートならではの機能：実戦日記、狙い方タグ、示唆タグで絞る、note用コピー（伏せ字の確認つき）
- 3段で作る。1段目は「既存の記録を全部読んで一覧・収支が見られる」まで。rec は触らない
- **rec の5MB問題が解決するのは第3段**（第1・2段では rec の保存は今のまま）

## 2. 画面

スマホ 390px 幅が主。片手で見られること。タップ領域 44px 以上。

### ① ホーム（今日）

```
今日 9/30(火)            +12,300円（3台）
 ├ 09:04 彼女、お借りします   DSG高岡  -5,538   [狙い：リセット]
 ├ 11:13 リコリス・リコイル   DSG高岡  +6,115
 └ ＋収支を登録
今月  +48,200円（41台）      想定期待値 +35,000
最近の記録（7日） …
[履歴]  [分析]  [取り込み]  [設定]
```

- 今日の台はカード。押すと②台の詳細
- 「今日」に記録が無い日は、最後に打った日を出す
- 履歴：月のカレンダー（日ごとの収支の色）→ 日を押すと②日の詳細

### ② 日の詳細・台の詳細

**日の詳細**
- その日の合計（現金・貯玉・合計円）、台のカード一覧
- **その日の日記**（自由記述）
- ［note用にコピー］（その日まとめて）

**台の詳細**
- 結果：投資・回収・貯玉の増減・収支・想定期待値・差（想定期待値より）
- 狙い方（主1つ）＋自由タグ
- 並び：**短い要約 → 印・タグの付いた行（節目）→ 全ログ**
- **節目**：開始・終了・収支の要約、行の種類が当選（hitStart）・終了（hitEnd）・お金（money）のもの、示唆タグの付いた行、「気になる」（第3段から）。
  判定は rec の元データの**行の種類（ev.type）と示唆タグ（ev.tags）だけ**で行い、文章から推定しない。行の種類を持たない出どころ（マイログ・遊タイム・kado-note のエンベロープ）は要約だけ
- ［全ログを開く］で数百行
- 示唆タグで絞る（設定示唆／モード示唆／…／自分で作ったタグ）
- **その台の日記**（自由記述が主）＋任意の問い2つ「何を狙って、どう判断した？」「次に同じ場面ならどうする？」。毎回の記入は求めない
- 「気になる」の印に、後から分類（続行判断／示唆／想定外／自分で作ったもの）。**印は第3段から**（第1・2段の画面には出さない）
- ［元の記録ツールで開く］（rec・かのかり・マイログ・遊タイム。辿れるものだけ）
- ［note用にコピー］

### ③ 分析

- 月別の棒と累積の折れ線は、390px では**切り替えで1つずつ**表示
- 絞り込み：期間（月）・種別（パチスロ／パチンコ）・機種（検索つき）・店・狙い方
- **機種 × 狙い方**の表を比較の主役に：件数・合計収支・1台平均・想定期待値の合計。集計は**主の狙い方1つ**で数え、自由タグでは数えない（二重に数えない）。途中で変えた台は「複合」
- 数字を押すと、その元になった日・台の一覧へ

### ④ 設定

- 取り込み（§5）、書き出し（バックアップ）・復元
- 店舗設定（今の rec から移す）
- 狙い方タグ・示唆タグの管理（名前の変更・削除）
- 保存容量の表示、永続化の依頼（ブラウザに「消さないで」と頼む：navigator.storage.persist）

## 3. データ（IndexedDB：slot-tools-note）

### 3-1. ストア

| ストア | キー | 中身 |
|---|---|---|
| plays | id | 1台＝1件（§3-2） |
| days | date（YYYY-MM-DD） | その日の日記・タグ |
| stores | id | 店舗と条件（rec の stores と同じ形） |
| tagDefs | name | 狙い方タグ・示唆タグ・印の分類の一覧（種類つき） |
| imports | id | 取り込みの履歴（いつ・どこから・何件） |
| meta | key | スキーマ版・設定 |

索引：plays に date・machine・shop・source・aim。

### 3-2. 1台の記録（play）

```js
{id, source:"rec"|"rec-kanokari"|"ledger"|"mylog"|"yutime", sourceId,   // 取り込み元と元の id
 date, startAt, endAt, kind:"slot"|"pachinko",
 machine, shop, dai,
 money:{cashIn, cashOut, withdraw, deposit, unit:"枚"|"玉"},             // 簡易収支と同じ考え方
 cond:{…}|null,                                                         // 交換条件（無ければ円換算しない）
 yen:number|null, units:number,                                         // 取り込み時に計算して持つ（表示を速く）
 expected:number|null,
 events:[…]|null,                                                       // rec 系は元のログをそのまま（示唆タグ・気になるを含む）
 raw:{…},                                                               // 元データの残り（捨てない）
 // ノートで足すもの（取り込み直しても消さない）
 aim:"リセット100G確認"|null, tags:[…], diary:"", marks:[{evId, cat}],
 mergedFrom:[…], importedAt, updatedAt}
```

### 3-3. 取り込み直し

- 同じ `source + sourceId` は**上書きではなく合流**：元データ側（money・events など）は新しい方に差し替え、ノート側（aim・tags・diary・marks）は残す
- 元の記録が消えていても、ノートの記録は消さない

## 4. 二重計上の防止

同じ台が複数の出どころから来る場合がある。

| 組み合わせ | 扱い |
|---|---|
| rec の実戦記録 ＋ 簡易収支（linkedSessionId あり） | 1件にまとめる。明細（events）は rec、収支は簡易収支（交換条件つき）を正とする |
| rec 本線 ＋ かのかり箱に同じ id | 1件（同じ記録の取り込み違い）。新しい方の元データを使う |
| rec ＋ マイログ／遊タイム（紐づけなし） | 自動ではまとめない。同じ日・店・機種が重なったら「同じ台ですか？」の候補を出し、夢爽が決める |
| 簡易収支の手入力 ＋ 遊タイム取り込み | 同上 |

まとめた記録は `mergedFrom` に元の id を全部持つ。まとめを解除できる。

## 5. 取り込み口

同じサイト（slot-tools.jp）なので、**ファイルを介さず、このブラウザにある記録を直接読める**。

| 出どころ | 読む場所 | 変換 |
|---|---|---|
| rec 本線 | localStorage `slot-tools-rec`（sessions・entries・stores） | session → play（events も。行の種類 ev.type・示唆タグ ev.tags をそのまま保持）、entry → play（source:"ledger"） |
| かのかり箱 | localStorage `slot-tools-rec-kanokari` | 同上 |
| マイログ（ジャグラー） | localStorage `juggler-mylog:v1` | 開始持ち＝引出、終了持ち＝預入。**貸出・交換は各記録の money.rate・exchangeMai を使う**（一律 46/52 にしない）。無い記録は未換算 |
| 遊タイム | localStorage（yutime-v3 の保存） | 9/28 に作った変換と同じ（方式A：台ごと、持ち玉の引き継ぎは引出に含める） |
| ファイル | JSON（上のどれの書き出しでも） | 形を見て判別 |

- 取り込み前に「新規 ○件・更新 ○件・同じ台の候補 ○件・未換算 ○件」を見せ、確認してから入れる
- 円換算できない記録は合計に入れず「未換算 n件（＋120枚）」と別に表示
- 取り込んだあとも、元のツールのデータは消さない（第1段）

## 6. note用コピー

構成：タイトル → 狙い → 実戦結果 → 節目（事実のみ）→ 本人の日記

```
【9月30日】彼女、お借りします
狙い：リセット100G確認
実戦結果：現金投資 5,000円／貯玉 +2,315枚／収支 +6,123円（1枚 4.8円換算）
節目：
・CZ（赤）→ かのかりBONUS
・1GレンCHANCE 3人攻略
― 日記 ―
（その台の日記）
```

- 日付は月日まで（曜日は付けない）
- 既定で伏せる：店名・台番号・正確な時刻。項目ごとのトグルで本人が表示を選ぶ
- 金額と枚数は単位を分けて書き、換算に使った条件を添える。未換算なら「枚」のまま
- コピーの前に全文をプレビュー。自動公開・自動送信はしない
- 生ログは含めない（節目だけ）

## 7. rec との関係（段階的に）

| 段 | rec | ノート |
|---|---|---|
| 1 | 変えない | このブラウザの rec・かのかり・マイログ・遊タイムを読む（手動の「取り込み」） |
| 2 | 収支帳の登録画面を外し「ノートで登録」へのリンクに。店舗設定もノートへ | 収支の登録・店舗設定・日記・狙い方・note用コピー |
| 3 | 台を終了したら、その台をノートへ送る（同じサイトなので直接書ける）。rec から古い台を消すのは、**ノートに入ったことを照合し（id と更新時刻が一致）、かつ書き出しのバックアップを取ったあと**に限る。rec の保存は「稼働中＋直近7日」。「気になる」1タップを追加 | 送られてきた台を自動で入れる。「気になる」の分類 |

rec の保存の仕組み（同期的に保存する作り）は第3段でも作り替えない。送る処理だけを足す。

## 9. 夢爽の裁定（10/1・すべて決定）

1. 名前：**稼働日誌**。URL：`tools/nisshi/`。今の kado-note.html（振り返りノート）は第3段で稼働日誌へ転送する
2. 同じ台の収支の正：rec の実戦記録と簡易収支が紐づいたら、**収支は簡易収支**（交換条件つき）、明細（ログ）は rec
3. rec に残す期間（第3段）：**直近7日**
4. 伏せ字：店名・台番号・正確な時刻は既定で伏せ、本人が項目ごとに表示を選ぶ。日付は月日まで
5. 狙い方タグ：**全機種共通のものと、機種専用のものの両方**。どちらも自分で作れる（tagDefs に scope：「全機種」または機種名）。台に付けるときは、その台の機種で使えるもの（共通＋その機種専用）を並べる

## 10. ネネのレビューで決まったこと（10/1）

- 節目：開始・終了・収支の要約、構造化された当選／終了／お金／示唆タグ、「気になる」（第3段）。文章から推定しない
- 台の詳細：要約 → 印・タグ付き行 → 全ログ
- 日記：自由記述が主、任意の問い2つ
- note用コピー：タイトル・狙い・実戦結果・節目・日記。プレビューで伏せ字と単位を確認
- 分析：棒と累積線は切り替え、機種×狙い方の表が主役
- 注記：rec の元データには行の種類と示唆タグがある（kado-note 用の書き出しでは memo に潰している）。ノートは元データを読むので構造化された節目が作れる
