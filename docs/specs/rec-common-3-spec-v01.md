## 0. 絶対ルール

1. 過去の記録（`sessions`・`entries`・稼働日誌の `plays`）の名前は**自動では書き換えない**。まとめるのは表示と集計のときだけ
2. 書き換えるのは、夢爽が「正式名に直す」を押した記録だけ。そのときも最初の名前を `machineTyped` に残す
3. マスターの名前・略称と**完全に一致する（下の比べ方で）ものだけ**まとめる。似ているだけのものはまとめない
4. `machineId`（専用記録の定義名：`generic`・`tokyoghoul` など）の意味は変えない
5. `js/machine-master.js` が読めなくても、今までどおり手入力で記録できる（開始を止めない）
6. 収支・口座・設定判別の計算は変えない

## 1. 機種マスター `js/machine-master.js`（シオン作成・同梱）

- 中身はシオンが作ったファイルをそのまま置く（md5 は指示書に記載）。classic script で `window.MachineMaster` を作る
- 1機種：`{mid, kind:"slot"|"pachinko", name, aliases:[…], recDef?}`
  - `name`：ちょんぼりすた「機種別一覧」の表記（2026-11-27 夢爽決定 A）。例外は p0004「Pスーパー海物語IN沖縄6」（夢爽の指定）
  - `mid`：`s0001`〜（スロット）・`p0001`〜（パチンコ）。一度付けたら変えない
  - `aliases`：今の呼び方と、夢爽のこれまでの記録の表記。夢爽の決定（からくりサーカス→2、ヴァルヴレイヴ→初代、モンスターハンターライズ→ライズ、モンスターハンターサンライズ→サンブレイク、ストリートファイター→6、ToLOVEる→Lとらぶるダークネス、モンキーターン→V、南国育ち→SPECIAL、パチンコのリコリス・リコイル→eリコリス・リコイル）を反映済み
  - `recDef`：専用記録がある機種だけ（`tokyoghoul`・`hibireturn`・`karakuri2`）
- 関数（使う側はこれだけを呼ぶ。比べ方を使う側で書き直さない）
  - `norm(name)`：全角半角・大文字小文字・カタカナひらがな・空白と記号の違いを無視し、頭の「スマスロ」「パチスロ」「スロット」「L」「S」を外す
  - `resolve(name, kind, mid)`：`mid` があればその機種。無ければ、同じ種別で `norm` が正式名か略称に一致する機種が**ちょうど1つ**ならその機種、それ以外は `null`
  - `search(q, kind, limit)`：前方一致を先、部分一致を後に、最大 `limit`（既定8）件
  - `byMid(mid)`
- 初期 81 機種（スロット77・パチンコ4）。夢爽の稼働日誌の機種名72種類すべてが `resolve` で1機種に決まることを確認済み
- 新台の追加：このファイルの末尾に1行足すだけ（番号は連番）。ほかのファイルは触らない

読み込み：`tools/rec/index.html`・`tools/nisshi/index.html` の `rec-store.js` の行の次に
`<script src="../../js/machine-master.js?v=20261127"></script>`。使う側は `window.MachineMaster` が無ければ「マスターなし」として今までどおり動く

## 2. rec：記録の項目

| 項目 | 付く記録 | 意味 |
|---|---|---|
| `mid` | 新しく始めた台（`S.cur` → `sessions`）・新しく登録した簡易収支（`entries`） | マスターの機種ID。候補から選んだとき、または入力した名前が `resolve` で決まったときに入れる。決まらなければ付けない |
| `machineTyped` | 「正式名に直す」を押した記録だけ | 直す前の名前。最初に直したときに1回だけ入れ、以後書き換えない |

- 形チェック：`mid`・`machineTyped` は「無い／文字列」なら可。それ以外は形が不正
- JSON 書き出し・取り込み・振り返りノート用：記録をそのまま出し入れする。振り返りノート用（`toEnvelope`）の `payload` に `mid` を足す（`machineId` は今までどおり `s.machine`）

## 3. rec：開始画面

- 機種名の入力欄 `#stMachine` の下に候補の行を置く。1文字以上入れると `search(入力, "slot", 6)` の結果をボタンで出す（ボタンの高さ 44px 以上、横に折り返し）
- 候補を押すと：欄に正式名、`pickedMid` に `mid`。`recDef` がある機種は今の専用機種ボタンを押したときと同じく `pickedMachine=recDef` にして専用項目を出す
- 今の機種ボタン（専用機種・最近の汎用機種4つ）は残す。最近の汎用機種は、記録の名前を `resolve` して正式名で出す（同じ機種が2つ並ばないように）
- 「打ち始める」：
  - `pickedMid` があればそれ、無ければ `resolve(入力, "slot")` の `mid` を `S.cur.mid` に入れる。決まった場合は `S.cur.machine` を正式名にする
  - 決まらない（マスターに無い）名前はそのまま記録する（今と同じ）。確認は出さない
  - 専用記録の判定（今の「「◯◯」には専用の記録画面があります」）は、`MACHINES[k].name` との一致に加えて、`resolve` した機種の `recDef` でも行う
- 専用記録の機種を専用ボタンから始めたときも、`mid` と正式名を入れる（例：東京喰種 → `mid:"s0001"`、`machine:"L東京喰種"`）

## 4. rec：簡易収支の登録

- 機種名の欄の `datalist` をやめ、§3 と同じ候補の行にする。種別は登録画面の種別（スロット／パチンコ）を使う
- 保存時：§3 と同じく `mid` と正式名を入れる（決まらなければ入れない）
- 実戦記録との紐づけ候補（今の `s.machine===e.machine`）は、両方を `machineKey()`（§6）で比べる

---

## 5. rec：未登録の印と「正式名に直す」

- 未登録：`machineKey(記録)` が名前のまま（マスターで決まらない）なら、ノートの台の一覧と詳細の機種名の後ろに小さく「未登録」（保存しない。毎回判定）
- 「打ち始め・終了の情報を直す」（`editInfo`）の機種名の欄の下に［正式名に直す］ボタン：
  1. §3 と同じ候補の行を出す（検索欄の初期値は今の名前）
  2. 選ぶと：`machineTyped` が無ければ今の名前を入れ、`machine` を正式名、`mid` を入れる
  3. 同じ名前（完全一致）の記録が sessions・entries にほかにもあれば「同じ名前の記録が◯件あります。まとめて直しますか？」→ はいなら同じ処理（各記録の `machineTyped` は各記録の元の名前）
  4. 保存
- `machineTyped` がある記録には［元の名前に戻す］：`machine=machineTyped`、`mid` と `machineTyped` を消す（1件だけ）
- 簡易収支の編集画面にも同じ2つのボタン

---

## 6. rec：ノートの集計と検索

- `machineKey(記録)`：`resolve(記録.machine, 種別, 記録.mid)` で決まれば正式名、決まらなければ記録の名前そのまま。**集計・機種ボタン・機種の絞り込み・紐づけの比較はすべてこの関数を通す**（`s.machine` を直接比べない）
- 機種ボタンの検索欄：`norm` で比べ、正式名と略称のどれかに含まれれば出す
- 表示：一覧・詳細の機種名は記録の名前のまま（夢爽が入れた名前を勝手に変えない）。集計の行と機種ボタンは正式名

---

## 7. 稼働日誌

- 取り込み（`recPlay`・`ledgerPlay`・`envelopePlay`）：記録に `mid` があれば play に `mid` を写す
- 表示と集計の名前（`displayPlay`）：まず `machineKey` と同じ方法で正式名にし（play の `kind` を使う）、その後に今の「名前をまとめる」（`repName`）を当てる。本人が作った代表名は今までどおり優先される
- 「名前をまとめる」の候補・「同じ台の候補」：正式名で比べる
- 既存の play・aliases・meta は書き換えない
