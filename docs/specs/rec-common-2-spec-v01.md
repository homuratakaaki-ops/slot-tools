## 2. 電卓（新しい部品 `openCalc`）

### 2-1 見た目
- 下から出るシート。今の `#kp` と同じ作り（`position:fixed`、背景暗く、`max-width:520px`）で、別の要素 `#calc`
- 上から：タイトル「クレジット」＋［キャンセル］／前回の値の表示（「前回 850（21:05）」、未入力なら「前回 未入力」）／式の表示（大きく）／計算結果のプレビュー（「= 850」、式が途中なら空）／エラー表示（赤・1行）／キー
- キー（4列）：
  ```
  7  8  9  ÷
  4  5  6  ×
  1  2  3  −
  00 0  C  ＋
  ```
  その下に1行：［⌫］［前回の値］［確定］
  その下に小さく：［未入力に戻す］（クレジットが入っているときだけ）
- キーの高さ 44px 以上

### 2-2 動き
- 開いたとき：式は空
- ［前回の値］：前回のクレジットを式の末尾に入れる（未入力なら何もしない）。例：前回 850 →［前回の値］［＋］［5］［0］→ 900
- 演算子の続けて入力：後の演算子で置き換える（`5＋×` → `5×`）。式の先頭に演算子は入れられない
- 計算の順：× ÷ を先、＋ − を後（普通の電卓と同じ）。途中の計算は整数のまま正確に（割り算は割り切れるか確かめる）
- ［確定］：
  | 状態 | 動き |
  |---|---|
  | 式が空 | 何もせず閉じる（クレジットは変えない・ログも増やさない） |
  | 式が演算子で終わる | 「式が途中です」と出して閉じない |
  | 割り切れない | 「割り切れません」と出して閉じない |
  | 0 で割る | 「0では割れません」と出して閉じない |
  | 結果がマイナス | 「マイナスになります」と出して閉じない |
  | 結果が大きすぎる（`Number.isSafeInteger` でない） | 「大きすぎます」と出して閉じない |
  | 0 以上の整数 | §3 の `setCredit` で確定し、閉じる |
- ［未入力に戻す］：確認なしで `setCredit(null)`、閉じる
- ［キャンセル］・背景タップ：何も変えずに閉じる

## 3. クレジットの記録（関数を1つにまとめる）

### 3-1 `setCredit(value, at)`
- `S.cur.money.credit = value`（null 可）、`S.cur.money.creditAt = value===null ? null : at`
- 変える前の値を `{prevCredit, prevCreditAt}` として返す
- 使う場所は §3-2 の3つだけ。ほかで `money.credit` を直接書き換えない

### 3-2 クレジットが入る経路
| 経路 | 今 | 段2 |
|---|---|---|
| 電卓で確定 | （残数調整）`askCredit` が `credit` を書き換え | `setCredit(v, nowISO())` → ログ `money`「クレジット 850枚（途中差枚 +74）」（未入力に戻したときは「クレジット 未入力に戻す」）。ログ行に `prevCredit`・`prevCreditAt` |
| CZ失敗・AT終了などの「今の持ちメダル」（汎用・からくりサーカス2・ハイビリターン30 など、`medalInput`） | `applyMedal` が `credit` を書き換え | `applyMedal` の中で `setCredit`。ログ `medal` に `prevCredit`・`prevCreditAt`。文言は今のまま（差枚は §4 の式） |
| 東京喰種の当選・CZ成功・CZ失敗・AT終了などの「今のクレジット」（ログの `cr`） | `cr` はログに入るだけ | **Q7：反映する**。`push()` の中で、行に数値の `cr` があれば `setCredit(ev.cr, ev.at)` を呼び、その行に `prevCredit`・`prevCreditAt` を付ける。`cr` 自体と区間の差枚の計算はそのまま |

### 3-3 取り消し（`undoLastOp`）
- 今は `money`・`medal` の行だけ `prevCredit` を戻している。これを「`prevCredit` を持つ行すべて」に広げ、`creditAt` も `prevCreditAt` で戻す（`prevCreditAt` が無い古い行は `null` に戻す）
- 1回の操作に複数の行がある場合は今と同じく後ろから戻すので、最初の行の「前の値」に戻る

## 4. 途中差枚の計算（関数を1つにまとめる：`midDiff(c)`）

```
クレジットが未入力         → null（表示は —）
creditAt が無い（旧データ）→ クレジット − 開始持ちメダル − round(投資の合計 ÷ 1000 × 貸出) − 再プレイの合計   … 今と同じ式
creditAt がある            → クレジット − 開始持ちメダル − round(creditAt までの投資 ÷ 1000 × 貸出) − creditAt までの再プレイ
```
- 「creditAt まで」＝ `spends`（旧形式は `cash`）・`replays` の各記録の `at` が `creditAt` 以下のもの
- 貸出は今と同じ `c.lend`（店舗を選んだ台は開始時に `cond.lend` が入っている）
- `stale`（※を出す）：`creditAt` より後の `spends`・`replays` が1件でもあれば true
- 戻り値：`{diff, stale}`。`renderMoney` と `applyMedal` の差枚表示はこの関数を使う（式を画面の中に別に書かない）
- 例：開始持ち 0、−1000（46枚貸し）、クレジット 120 → +74。その後 −1000 → +74 のまま ※
- `profit()`（終了時の収支）は変えない

## 6. 保存・読み込み・書き出し
- `money.creditAt`：ISO 文字列 または null。無い台はそのまま（旧データ扱い）
- 読み込み時の形チェック（`validSession` の `money` の検査）：`creditAt` は「無い／null／`dateOk` な文字列」なら可。それ以外の台は今の検査と同じく「形が不正」
- `fixSession`：`credit` が null なのに `creditAt` がある場合は `creditAt` を null にする（補完のみ）
- JSON 書き出し・取り込み：台をそのまま出し入れするので追加の処理なし（`creditAt` も一緒に往復する）
- 振り返りノート用（`toEnvelope`）・稼働日誌：変更なし
- 古い版のページで読んでも、知らない項目は消えない（確認済みの作り）
