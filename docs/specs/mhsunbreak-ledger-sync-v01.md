# モンハンサンブレイク：テーブル別集計とAT間メモの同期 v01

発行：シオン 2026-10-18（指示書 fix/mhsunbreak-1018）／仕様書起こし：ツムギ
依頼元：ネネ「シオンへの修正依頼｜モンハンサンブレイク設定判別チェッカー」（10/18。カウンター35件・履歴33件のズレ）＋夢爽承認（11個目）

## 0. 設計の要点

- 集計（テーブル別の回数・成功数）＝ **履歴なし分（base）＋ AT間メモから自動集計（derived）**。
- ボタン押下で集計を直接増減する処理は廃止する。履歴の削除・差し込みは集計に自動で反映される。
- 既存データの合計値は移行で変えない（例：35件は「履歴33＋履歴なし2」として35のまま）。

原因：テーブル別集計（bzT1/bzT2/questN1/questN2）とAT間メモ（atLog）が別々に保存され、
削除・減算・差し込みが片方しか動かなかった。

## 1. 保存形式

- 新キー `S.bzBase = {bzT1:{t1..t7}, bzT2:{..}, questN1:{..}, questN2:{..}}`（履歴なし分）。
- 旧トップレベルの `bzT1/bzT2/questN1/questN2` は移行後に削除。`MERGE_KEYS` から外し `'bzBase'` を入れる。
- 移行（normalizeState。**読み込んだ生データ src に bzBase が無いときだけ**1回）：
  `bzBase[key][id] = max(0, 旧 S[key][id] − derived(全セッション)[key][id])`。
  その後 questN ≦ bzT をグループごとに保つ（§9-87）。
  旧 iconLog（10マス配列）の移行加算は bzBase に入れる（履歴が無いため）。
  - engine の normalizeState は `Object.assign(clone(DEF),src)` と mergeKeys の浅いマージを先に行うため、
    旧データでも `out.bzBase` は既定値（全0）で埋まっている。**判定は src で行う。**
- bz 出来事に任意項目 `g`（`'bzT1'|'bzT2'`）を追加。開始不明のAT間で記録するときに、選んだ計上先を保存する。
  normalizeAtEvent は g が上記2値のときだけ残し、それ以外は項目ごと落とす。

## 2. 自動集計 derived(S)

各セッションの bz 出来事の計上先：

- `start.known` → `bzNoAt(session,index)===1 ? 'bzT1' : 'bzT2'`
- `start.known` でない → `e.g` があればその値。無ければ計上しない（履歴なし分に含まれているとみなす）

計上先 D に +1、`r==='win'`（t7 は常に win）なら対応する N に +1。

公開関数 `totals(S) = base + derived`。集計表示・questD/questHit・テンプレ・カード・シナリオカードはすべて totals を使う。

**セッションを捨てるときは合計を減らさない。** 捨てるセッションの derived を bzBase に足してから捨てる。対象は
addAtEvent の shift（AT_SESSION_MAX 超過）と、normalizeAtLog の `slice(-AT_SESSION_MAX)` の両方。

## 3. 操作

| 操作 | 新しい挙動 |
|---|---|
| BZ記録（bzQuestAction 加算側） | 出来事の追加のみ。開始不明なら `event.g=dKey` |
| 経過の［削除］（atDelAction） | 出来事を削除するだけ（集計は自動で減る） |
| 減算モード（集計の中のボタン） | bzBase だけを減らす。bzBase に減らせる分が無い行はボタンを無効化 |
| 差し込み | 後ろのBZの番号が変わると、計上先も自動で移る |
| 取消（engine の undo） | 状態全体（変わったキー）を戻す現行どおり。変更なし |

- 集計セクションの表の下に「うち履歴なし：1回目 X回（成功Y）／2回目以降 X回（成功Y）」を1行（両方0なら出さない）。
- 「成功／失敗の訂正」操作は現在存在しないため今回は作らない。

## 4. 結果アイコン11個目・猛焔一閃

- `ICON_POS_MAX=11`。pos 11 は全テーブル共通で `'猛焔一閃'`（TABLE_ICONS は10要素のまま、配列外として特別扱い）。
- 入口（inputPosPicker）：10個の後に「11：猛焔一閃（AT）」。押したら pickPos=11 で**即座に成功として記録**する。t7 は従来どおり位置1固定。
- 既存カード（posPicker）：pos 11 は `r==='win'` のときだけ選べる。normalizeAtEvent も miss の pos 11 は項目ごと落とす。
- 説明文：入口側＝「11個目は猛焔一閃（AT）です。押すと成功として記録されます。」／既存カード側＝「11個目は猛焔一閃（AT）です。成功の記録にだけ付けられます。」（夢爽 10/18）
- **テンプレには結果アイコン（pos 11 を含む）を出さない**（v05 の出力を変えない）。猛焔一閃と出るのは手順3のラベル・経過カード・BZシナリオカードだけ。指示書 4(e) の「テンプレ表記」は取り下げ（夢爽 10/18）。

## 5. 既存データへの影響

- 移行の式：`bzBase[key][id] = max(0, 旧集計[key][id] − 履歴からの集計[key][id])`（その後 questN ≦ bzT をグループごとにクランプ）。
- 例：1回目①が35件・AT間メモの履歴が33件 → 履歴33＋履歴なし2 で合計35のまま。
- **例外：旧集計＜履歴のテーブルは、合計が履歴の件数まで戻る**（max(0, …) で履歴なし分が0になり、履歴の分はそのまま数えるため）。
  旧版で、履歴を残したまま減算モードで集計だけを減らしていた場合に起きる。
- 開始不明のAT間にある旧い出来事（g が無い）は計上先が分からないため、履歴なし分に含めたままにする。
  この出来事を［削除］しても集計は減らない。直すときは減算モードを使う。
