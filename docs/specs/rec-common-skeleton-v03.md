## 0. 要するに

4つの要望を、**保存データに触る量が少ない順に3段**に分けて進めます。

| 段 | 中身 | 保存データへの影響 | ゲート |
|---|---|---|---|
| 段1 | ③ 開始時の「再プレイでおろした分」欄の廃止／② 店舗の利用順 | **なし**（並び順は過去の記録から毎回計算） | **通過** |
| 段2 | ④ クレジット・途中差枚の2段表示と電卓 | 小（入力した時刻 `creditAt` を1項目足す） | 通過（Q7 決定済み） |
| 段3 | ① 機種マスター（正式名・略称検索・機種ID・表記ゆれ統合） | あり（新しい台に機種IDを足す・共通ファイル新設） | 通過（Q1〜Q3 決定済み） |

コードを読んで分かった大事な点が3つあります。

1. **「クレジット」の器はすでにある。** 実戦中の `money.credit`（「残数調整（今の持ち玉を入れて差枚を出す）」）がそれで、差枚マスはこの値から出ています。④は新しいデータを作るのではなく、**今の器の入力方法と表示を作り直す**話です。
2. **今の途中差枚には「入力した後に投資すると数字がずれる」問題がある。** クレジットを入れた後に −1000 を押すと、クレジットは古いまま投資分だけ引かれ、差枚が実際より悪く出ます（§4-3）。
3. **稼働日誌にはすでに「名前をまとめる」（表記ゆれ統合）がある。** ①の「過去の表記ゆれを集計で統合」と重なるので、日誌の仕組みを捨てずに、機種マスターは「正式名の辞書」として足す形にします（§1-6）。

## 1. 機種名の統一（段3）

### 1-1 目的
- 新しく記録するときは**正式名で登録**し、**機種IDで同じ機種を見分ける**
- 略称・別名でも探せる
- 過去の記録の名前は**書き換えず**、集計のときだけ同じ機種としてまとめる

### 1-2 機種マスターの置き場所と形（案）
- 新しい共通ファイル `js/machine-master.js`（rec・稼働日誌の両方から読む）
- 1機種の形：
  ```
  { mid:"s0012", kind:"slot", name:"（正式名）", aliases:["略称","旧表記",…], recDef:"tokyoghoul" }
  ```
  - `mid`：機種ID。**一度付けたら変えない・使い回さない**
  - `kind`：`slot`／`pachinko`
  - `aliases`：略称・別名・過去の表記ゆれ（検索と集計の両方に使う）
  - `recDef`：rec の専用記録画面がある機種だけ、その定義名（`karakuri2`・`tokyoghoul` など）
- 今の `js/machines.js`（ジャグラー記録の一覧用略称）とは用途が違うので統合しない

### 1-3 記録への入り方
- 新しく始める台・新しく登録する簡易収支に `mid` を1項目足す。`machine`（名前）は今までどおり正式名で入れる
- 既存の `machineId`（専用画面の定義名。`generic` など）は意味を変えない。`mid` とは別物
- 過去の台・簡易収支には**何も足さない・何も書き換えない**
- マスターが読めなかったとき（電波・キャッシュ）：今と同じ手入力で始められる。`mid` は空のまま。**記録開始を止めない**

### 1-4 検索
- 開始画面の「機種」と簡易収支の「機種名」で、入力すると候補を出す
- 比べ方：全角半角・ひらがなカタカナ・空白・記号の違いを無視（NFKC＋かな統一）。正式名と `aliases` の両方を見る
- 候補を選ぶと欄には正式名が入る。候補を選ばずに打ち始めたときの扱いは §1-8

### 1-5 新台の追加と読み込みの重さ
- 追加は「マスターのファイルに1行足す」作業。シオンが出典（Q1）で名前を確かめ、実装担当が commit する
- 重さの見込み：1機種 約120バイト。500機種でも約60KB。開始画面を開いたときに1回読むだけで、打っている最中には読まない。**体感の遅れはほぼ出ない見込み**（実測は段3の検証項目に入れる）
- 新台初日にまだマスターに無い場合の逃げ道は §1-8

### 1-6 過去の表記ゆれの統合（集計のときだけ）
- 名前 → `mid` を決める順番（1つの関数にまとめる）：
  1. 記録に `mid` があればそれ
  2. 無ければ、名前がマスターの正式名か `aliases` に一致すれば、その `mid`
  3. どれにも当たらなければ、名前のまま（統合しない）
- 稼働日誌の「名前をまとめる」（本人が決めた代表名）は今までどおり残す。マスターは「候補を出す材料」として使い、**本人が違うと決めた組（notSameName）は上書きしない**
- 「ハイビリターン」と「ハイビリターン30」のような例は、マスター側で `aliases` に入れて統合する

### 1-8 マスターに無い機種（Q2 決定：手入力 → 後から正式名に直す）
- 候補を選ばずに名前を打って始めると、今までどおり汎用で始まる。`mid` は空。画面とノートでは機種名の横に「未登録」と出す（`mid` が空で、名前がマスターに無いことから毎回判定。印は保存しない）
- 後から直す：ノートの台の詳細（または「打ち始めの情報を直す」）に「正式名に直す」を置き、マスターの候補から選ぶ
  - 直すと `mid` と `machine`（正式名）が入る。**最初に打った名前は `machineTyped` に1回だけ写して残し、以後書き換えない**（元の入力を失わない）
  - 同じ手入力名の記録がほかにもあれば「同じ名前の◯件もまとめて直しますか」と聞く
  - 取り消し：`machineTyped` から元の名前に戻し、`mid` を空にする
- マスターに入る前の機種でも、手入力の名前どうしは今までどおり名前で集計される
- 東京喰種などの専用画面（`machineId`）は直しても変わらない。名前と `mid` だけが変わる

### 1-7 対象範囲（案）
- rec：開始画面・簡易収支の登録・ノートの機種検索と集計
- 稼働日誌：集計のまとめ（段3の後半、3b）
- 遊タイムツール（パチンコ）・マイログ・rec-kit・rec-kanokari：**今回は対象外**
- パチンコ機種：簡易収支でパチンコも登録するので、マスターには入れる（Q3）

## 2. 店舗選択画面（段1）

### 2-1 並び順
- 「店舗を選ぶ」シートの店を、**その店で最後に打ち始めた時刻の新しい順**に並べる
- 最後に使った店は一番上に、ボタンを大きく（高さ・文字を一段大きく）表示
- 一度も使っていない店は、その下に今までどおりの登録順

### 2-2 「利用順」をどう持つか → 保存しない
- 並び順は、実戦記録（終わった台＋今の台）の `storeId` と `startAt` から**毎回計算**する
- 新しい項目は保存しない。これで次の2つが自動的に満たされます：
  - 実戦開始時に更新される（台が始まったときに記録ができるので）
  - **キャンセルしたら更新されない**（台が始まらなければ記録が無いので）
- 台を破棄・削除したら、その分は並び順に効かなくなる（記録が無いので当然そうなる）

### 2-3 数える台（Q4）
- **決定（Q4）**：店舗設定から選んで始めた台に加えて、**店名を手入力した旧方式の台も、店名が一致すれば数える**（空白・全角半角の違いは無視）。簡易収支は数えない

### 2-4 同じ並びにする画面
- 推奨：①打ち始めの「店舗を選ぶ」、②簡易収支の登録の店ボタン。③「店舗設定」の一覧は登録順のまま（編集するときに位置が動くと探しにくいため）

## 3. 開始時入力の簡略化（段1）

### 3-1 やること
- 開始画面の「再プレイでおろした分」欄を消す
- 下の案内文を「打ち始めに貯メダルからおろす分も、打ち始めてから『再プレイ』ボタンで記録します」に変える

### 3-2 変えないもの
- 再プレイの記録先（`money.replays`）・取り消し・上限と残高の確認・口座の計算・収支の式
- 過去の台に入っている「打ち始めの再プレイ」（`atStart:true` の記録）はそのまま。表示も計算も変わらない
- 店舗を選ばない旧方式の台の「貯メダル残高（おろす前）」欄は残す

### 3-3 影響の確認結果
| 場面 | 影響 |
|---|---|
| 店舗を選んだ台 | 開始時の上限・残高の確認（`acctAllowReplay`）は、開始後の「再プレイ」ボタンで同じものが出る。結果は同じ |

| 23:59 に始めて 0:00 過ぎに再プレイ | 再プレイの日付が翌日になり、翌日の上限に数えられる。実際の店の機械と同じ動きなので問題なし |
| 書き出し・取り込み・日誌 | 形式は変わらないので影響なし |

## 4. クレジット・途中差枚の表示（段2）

### 4-1 画面
- 今の「差枚」マスを上下2段にする
  - 上段：**クレジット**（未入力なら「—」）
  - 下段：**途中差枚**（クレジット未入力なら「—」）
- マスをタップすると電卓が開く。今の「投資・回収・出力」→「残数調整」も同じ電卓を開く（入口が2つ、処理は1つ）

### 4-2 電卓
- キー：0〜9・00・＋・−・×・÷・C（全部消す）・⌫（1字消す）・キャンセル・確定
- 開いたときの表示：前回の値があれば「前回 850」と小さく出し、入力欄は空
- 直接入力：`850` → 確定で 850
- 加算入力：`50＋800` → 確定で 850。前回の値に足したいときは「前回の値を入れる」ボタンで 850 を入れてから ＋ を押す（Q6）
- 確定できるのは **0以上の整数**だけ。割り算で端数が出る・マイナスになる・式が途中で終わっている場合は、理由を出して確定させない
- 何も入れずに確定 → 何もしない（**0として記録しない**）。0を記録したいときは 0 を押して確定
- 「未入力に戻す」ボタン：クレジットを未入力（—）に戻す（誤って入れたとき用）

### 4-3 途中差枚の計算（1つの関数にまとめる）
今の式：`クレジット − 開始持ちメダル − 投資で借りた枚数 − 再プレイ`
問題：投資と再プレイを「今この瞬間の合計」で引くので、クレジットを入れた後に −1000 や再プレイをすると数字がずれる。

**案（推奨）：入力した時点の途中差枚として計算する**
```
途中差枚 = クレジット − 開始持ちメダル − 入力時刻までの投資で借りた枚数 − 入力時刻までの再プレイ
```
- このために、クレジットを確定した時刻 `money.creditAt` を1項目保存する（Q5）
- 入力後に投資・再プレイがあったら、下段に「入力後に投資あり」と小さく出し、入れ直しを促す
- 例：開始持ち0、1,000円（46枚）投資、クレジット120 → 途中差枚 +74。その後 −1000 を押しても +74 のまま「入力後に投資あり」と出る（今の作りでは +28 に下がってしまう）
- `creditAt` が無い過去の台・今の台は、今と同じ式で出す

### 4-4 変えないもの（勝手に動かさない）
- 最終の持ちメダル（`endMedal`）・投資の記録・再プレイ・口座（貯メダル残高）・簡易収支には何も書かない
- 収支（円）の計算は今のまま
- 「やめる」画面の持ちメダル欄は、今と同じく最新のクレジットを**初期値として入れるだけ**（保存は本人が「終了する」を押したとき）（Q6 決定：今までどおり）
- 今も CZ失敗・AT終了などのシートで入れた「今の持ちメダル」は `money.credit` に入り、差枚マスとやめる画面の初期値に反映されている（汎用・からくりサーカス2・ハイビリターン30 など）。この動きは変えず、上段のクレジットにも同じ値が出る

### 4-5 取り消し・再開・書き出し
- 確定すると今と同じくログに1行（文言は「クレジット 850枚（途中差枚 +74）」）。「直前を取り消す」で前の値と前の時刻に戻る
- 再開（ページを開き直す）：`credit`・`creditAt` は今の台と一緒に保存済みなので、そのまま出る
- JSON：今の台・終わった台に `creditAt` が入るだけ。古い版で読んでも項目は消えない（店舗連動 v1.0 §5.4 で確認済みの作り）

### 4-6 電卓の共用と、混同しないための決まり
- 電卓は「数字を1つ作る部品」にし、**何の値かは呼び出す側が決める**
- 段2で使う場所：実戦全体のクレジット（`money.credit`）
- 東京喰種だけ動きが違う：当選・CZ成功・CZ失敗・AT終了で入れる「今のクレジット」はログの `cr`（区間の差枚用）にだけ入り、**`money.credit` には入っていない**。そのため今の東京喰種では、ここで入れた値は差枚マスにも、やめる画面の初期値にも出ない（Q7）
- **Q7 決定（反映する）**：`cr` を確定したとき、同じ値・同じ時刻を `money.credit`・`creditAt` にも写す。区間の差枚は今までどおり `cr` どうしの差で出し、実戦全体の途中差枚は §4-3 の式で出す（**値の出どころは同じ画面の数字でも、計算は混ぜない**）。取り消すと両方戻る
- 東京喰種の入力欄そのものを電卓にするかどうかは、段2の後に別途決める（今回は入れない）

## 5. 東京喰種専用recと競合しない進め方

- どちらも同じ1ファイル（`tools/rec/index.html`）を直す。東京喰種は「機種定義」と「当選・終了のシート」、共通改修は「開始画面・お金のマス・電卓・店舗シート」で、**触る場所はほぼ分かれている**
- 決まり：
  1. 各段は、その時点の main の最新から作業ブランチを切る
  2. 東京喰種の改修と同時に進む場合は、**先に終わった方を先に main へ**。後の方は main を取り込み直してからテスト
  3. 各段の検証で、東京喰種の回帰テスト（`tests/rec-tokyoghoul*.mjs`）を毎回通す
  4. 段2で東京喰種の区間クレジットの欄には触らない（§4-6）
