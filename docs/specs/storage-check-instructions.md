# 指示書：保存容量チェックページの配置（tools/storage-check）

宛先：ツムギ（Claude Code）　発行：シオン　2026-10-29

## 背景
- tools/rec で「保存できません」が出て、記録が保存できなくなった（夢爽のスマホ、10/27〜）
- 10/29 時点のバックアップでは tools/rec のデータは約137万文字。取り消し用の控え（snap）は容量不足時の自動縮小（stripSnaps）ですでに外れている
- ブラウザの保存枠は slot-tools.jp 全体で約524万文字（Chromium で実測）。rec 以外のキーが残り約380万文字を使っている可能性が高い
- 候補：`slot-tools-rec-broken` など読み込み失敗時の退避コピー（消す処理がない）、`slot-tools-rec-kit` / `slot-tools-rec-kanokari` とそれらの `-broken`、`nerai_record_v1_*` の控え、チェッカーの `-rec-bak`
- 何が場所を取っているか実機で測るため、読み取り専用の診断ページを置く

## 作業内容
1. 新しいブランチ `feature/storage-check` を作る
2. シオンが作った `tools/storage-check/index.html` を、そのままの内容で配置する（中身は変更しない）
3. この指示書を `docs/specs/storage-check-instructions.md` として同じブランチに含める
4. 導線は作らない（トップ・ナビ・サイトマップには載せない）。ページは noindex 済み
5. index.html の NEW 欄には載せない（利用者向けツールではないため）

## 検証手順
1. 新規ファイルが記録データを書き換えないことをコードで確認する
   - `setItem` は `__slot_tools_storage_probe__` だけ、`removeItem` も同じキーだけであること
   - 測定後に `finally` で仮データが必ず消えること
2. Playwright（390px幅）で次を確認する
   - 適当なキーを2つ入れて再読み込み → 内訳に大きい順で出る
   - 「空き容量を測る」→ 数字が出る／仮データのキーが残っていない／入れたキーの中身が変わっていない
3. 公開後、`https://slot-tools.jp/tools/storage-check/` が表示されることを確認する
4. 配置したファイルの md5 を報告する（シオンが原本と照合する）
