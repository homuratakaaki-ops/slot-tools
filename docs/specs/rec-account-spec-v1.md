## 0. 最優先の守り（変更禁止条件）

1. **既存データは書き換えない。** 既存の実戦記録（sessions）・簡易収支（entries）・店舗（stores）の値、ID、計算結果は1件も変えない。新しい計算は「新方式で始めた台」だけに効く。
2. **お金・メダルの事実は1か所にしか書かない。** 再プレイは今までどおり台の `money.replays` だけに書く。口座側に同じ再プレイを二重に書かない。
3. **残高・手持ち・本日の再プレイ累計は保存しない。** 毎回、元の記録から計算する。
4. **預け入れは「手元→貯メダル」の移動であり、収支ではない。**
5. **店舗を選ばずに始めた台は今までとまったく同じ動きをする。**（自由入力の店名・手入力の貸出は残す）

## 1. D3 店舗データ（確定）

### 1.1 結論
- **店舗の正本は rec 内の `S.stores` のまま。** 共通マスタ `slot-tools-stores-v1` とは今回つながない（移行・名寄せ・ID振り直しをしない）。
- 理由（コード照合の結果）：
  - `slot-tools-stores-v1` を読み書きしているのは `sf6-record.html` だけ。rec・稼働日誌（nisshi）・rec-kanokari は使っていない。
  - 稼働日誌は rec と同じ `{id,name,conds:[…]}` 形の店舗をそのまま取り込んでいる。rec の店舗IDを変えると日誌側の対応が切れる。
  - 共通マスタは店舗×種別に代表レート1組しか持てず、①（同じ店でもレート別に管理）を表せない。
- 共通マスタとの統合は **別案件**（IDEAS.md 候補）。本改修では触らない。

### 1.2 レート条件（`S.stores[].conds[]`）に足す項目
| 項目 | 型 | 意味 |
|---|---|---|
| `replayUnit` | 正の整数 or `null` | 再プレイ1回の枚数。`null` なら従来どおり貸出枚数を使う |
| `replayLimit` | `{mode, value}` | 1日の再プレイ上限。`mode` は `"unset"`（未登録）／`"none"`（上限なし）／`"fixed"`（上限あり）。`value` は `fixed` のときだけ 0 以上の整数、他は `null` |

- 既存の条件は読み込み時に `replayUnit:null`、`replayLimit:{mode:"unset",value:null}` を補う（保存値の上書きではなく欠けた項目の補完）。
- **未登録（unset）を「上限なし」と扱わない。** 未登録のときは残りを「—（上限未登録）」と表示し、引出しの確認は出さない。`fixed` の 0 は「再プレイできない店」。
- `fixStores()` は今、条件を作り直す際に知らない項目を落とす。**知らない項目を残す形に直す**（稼働日誌側の追加項目を消さないためにも必須）。

### 1.3 口座（貯メダル口座）
- 口座の鍵：`accountKey = storeId + "|" + condId`（①：店舗×レート条件ごと）。口座の一覧は保存しない（条件があれば口座がある）。
- レート条件の数値（貸出・交換）を後から変えても口座は同じ。過去の台は台ごとに保存した条件の写し（§3.1）で計算するので、過去の収支は変わらない。
- 店舗名の変更も口座に影響しない（IDで結ぶ）。
- **記録が付いている店舗・条件は削除できない。** その店舗・条件を使った台、または口座の記録（§2）がある場合、削除ボタンは「記録があるため削除できません」と表示して何もしない。

## 2. 口座の記録（`S.ledger`）

### 2.1 置き場所（D5 の中心）
- **localStorage の rec 本体（キー `slot-tools-rec`）の中に `ledger` として置く。** IndexedDB の版は上げない（`js/rec-store.js` は変更しない）。
- 理由：
  - 稼働中の台（`cur`）・店舗・簡易収支・未確定の書き込み予定（outbox）は、すでに localStorage の1回の書き込み（1つのJSON）で保存されている。口座の記録も同じJSONに入れれば、**「台の終了」と「預け入れ」と「自動預入」が1回の保存でまとめて確定する**（途中で落ちても片方だけ残ることがない）。
  - 複数タブは既存の世代番号（`gen`）の仕組みがそのまま効く。古いタブは保存できずに凍結される。
  - IndexedDB の版上げは稼働日誌の読み取り（同じ `rec-store.js` で版2を開く）にも影響するため避ける。
- 容量：1日あたり数件・1件150バイト前後で、年間でも100KB未満の見込み。再プレイは台の中（終了後は IndexedDB）にあるので localStorage は増えない。

### 2.2 形
```json
"ledger": {
  "ver": 1,
  "events": [ { ...event } ],
  "quarantine": []
}
```
event の項目：
| 項目 | 型 | 説明 |
|---|---|---|
| `id` | string | 下の決め方で作る。重複判定の鍵 |
| `type` | `"balanceSet"`／`"finalDeposit"`／`"autoDeposit"`／`"settleSkip"` | 種類 |
| `storeId`,`condId` | string | 口座 |
| `dayKey` | `"YYYY-MM-DD"` | JSTの日付（balanceSet は入力した日） |
| `amount` | 0以上の整数（settleSkip は `null`） | 枚数 |
| `at` | ISO文字列 | 計算上の時刻（下記） |
| `createdAt`,`updatedAt` | ISO文字列 | |
| `status` | `"active"`／`"void"` | 取消は `void` にするだけ。消さない |
| `verified` | boolean | autoDeposit は `false`（未照合）。夢爽が確認したら `true` にできる |
| `edits` | `[{at,field,from,to}]` | 直した履歴 |
| `note` | string | 任意 |

id の決め方：
- `autoDeposit`：`"auto:" + accountKey + ":" + dayKey`（**同じ口座・同じ日に1つしか存在できない**）
- `finalDeposit`：`"final:" + accountKey + ":" + dayKey`（同上。入れ直しは同じ記録を直す）
- `settleSkip`：`"skip:" + accountKey + ":" + dayKey`
- `balanceSet`：`uid()`（何度でも作れる）

`at` の決め方：
- balanceSet：入力した時刻
- finalDeposit：その日の稼働中に入れたら入力時刻。翌日以降に入れたら「その日の最後の台の終了時刻」
- autoDeposit：「その日の最後の台の終了時刻」

### 2.3 種類ごとの意味
- **balanceSet（残高を合わせる）**：その時点の貯メダル残高を実数で登録する。初めて管理する口座の初期残高、ずれたときの合わせ直しの両方に使う。最新の balanceSet が基準になる。
- **finalDeposit（最後に貯メダルへ預けた枚数）**：D2。入力した枚数だけ残高に足す。入力した日の手持ちは 0 になる。手持ちより少なければ差を「行先未記録」として表示する（残高にも収支にも足さない）。0 の入力は「入力済み・0枚」で、自動預入を止める（未入力とは別）。
- **autoDeposit（翌日の自動預入）**：③。§4 の条件で1回だけ作る。未照合表示。直す・取り消すことができる。
- **settleSkip（預入なしで締める）**：「預けていない／分からない」日を締めて、確認の表示を消すための印。残高は動かさない。

## 3. 台（session）に足す項目と計算

### 3.1 新方式の台だけに足す項目
店舗とレート条件を選んで始めた台にだけ、次を保存する：
| 項目 | 内容 |
|---|---|
| `storeId`,`condId` | 口座 |
| `cond` | 開始時の条件の写し `{kind,lend,exchPer1000,exch,label,replayUnit,replayLimit}`（後で店舗設定を変えても動かない） |
| `lend` | `cond.lend`（既存項目。互換のため従来どおり入れる） |
| `shop` | 店舗名（既存項目。従来の表示・出力のため入れる） |
| `money.startMedal` | 開始時の手持ち（§4.3 の値を初期値にして、本人が直せる） |

- 店舗を選ばなかった台には何も足さない（従来と同じ）。
- 新方式の台では、台ごとの `money.stockStart`（貯メダル残高の手入力）を使わない（口座の残高で代える）。旧方式の台の欄と動きは残す。

### 3.2 収支の計算（profit）
- **新方式の台（`cond` が正しく入っている台）**：
  - 差枚 `units = endMedal − startMedal − 再プレイ合計`
  - 収支（円）`= Math.round(units × cond.exch) − 現金投資`
  - `cond.exch` は「1枚あたりの円（小数第2位まで）」。簡易収支の `entryStockYen` と稼働日誌の `calculatedYen` と同じ式にそろえる。
  - 例：46枚貸し・52枚交換、現金1,000円・46枚持って終了 → 46×19.23＝884.58→885、885−1,000＝**−115円**
- **旧方式の台**：今の式（貸出枚数で円換算）のまま。過去の合計は1円も変わらない。
- 「やめる」画面の収支の見込み表示も同じ関数で出す（今は式を画面内に別に書いているので、関数を呼ぶ形に直す）。
- **預け入れ・自動預入・行先未記録は収支に入れない。** 収支は台の中の増減（手持ちの終了−開始−再プレイ）と現金だけで決まる。最後に何枚預けたかは「残高の管理」の話で、収支の話ではない。
- 簡易収支と紐づいた台は、今までどおり簡易収支の側を使う（`agg` の優先ルールは変えない）。
- 口座の残高計算に簡易収支（entries）の引出・預入は**使わない**（同じ日を二重に数えないため）。

### 3.3 口座の値（表示用・保存しない）
JST の日付：`jstDay(t) = new Date(Date.parse(t) + 9*3600*1000).toISOString().slice(0,10)`（端末のタイムゾーンを使わない）。

- 台の所属日 = `jstDay(startAt)`
- 再プレイの日 = `jstDay(replay.at)`
- **本日の再プレイ累計 U(口座, 日)**：その口座の台（稼働中＋終了済み）の `money.replays` のうち、再プレイの日がその日のものの合計
- **貯メダル残高 A(口座)**：最新の active な balanceSet を基準に、
  `A = 基準の枚数 + Σ(基準より後の active な finalDeposit / autoDeposit の amount) − Σ(基準より後の再プレイ)`
  - balanceSet が1件もなければ A は「未登録」。0 とはしない。
  - 「後」は `at` で比べる。
- **手持ち H(口座, 日)**：
  - その日に finalDeposit か settleSkip があり、その `at` より後に終わった台がなければ 0
  - そうでなければ、その日の最後に終わった台の `endMedal`
  - その日に終わった台がなければ 0
- **あと再プレイできる枚数**：`fixed` のとき `max(0, value − U)`。`none` は「上限なし」、`unset` は「—」。

### 3.4 再プレイの記録
- 記録先は今までどおり `S.cur.money.replays`（`tk` 付き）。取り消しも今までどおり（取り消せば U と A は自動で戻る）。
- 新方式の台で、記録すると U が上限を超える、または A（登録済みのとき）がマイナスになる場合は、**確認を出して、はいなら記録する**。拒否はしない。
  - 理由：本当の上限と残高は店の機械が決めている。ツールの残高は自動預入などの推定を含むので、ツール側で記録を拒むと「実際に起きた再プレイが記録できない」＝記録が消える。

## 4. 日付と自動預入（D1・D2・③）

### 4.1 日付
- JST の午前0時で切り替える（D1）。U と自動預入の判定は同じ `jstDay` を使う。

### 4.2 自動預入の判定（1回だけ）
実行する時：起動直後（読み込み完了後）／画面が再表示されたとき（visibilitychange）／新しい台を始める直前。

各口座について：
1. balanceSet が1件もない口座は対象外（残高を管理していない）。
2. `L` = その口座で終了済みの台がある最新の所属日。
3. `L >= 今日（JST）` なら何もしない。
4. その口座に稼働中の台（`S.cur`）があれば保留。
5. `(口座, L)` に finalDeposit・autoDeposit・settleSkip のどれか（active）があれば何もしない（D2：入力済みなら自動にしない）。
6. 最新の balanceSet の `at` が L の最後の台の終了時刻より後なら何もしない（残高を合わせた時点で反映済み）。
7. L の最後の台の終了時刻の JST 日付が L でなければ（0時をまたいで終わった）、**保留＝要確認**。
8. それ以外なら autoDeposit を作る：`amount = H(口座, L)`、`at` = L の最後の台の終了時刻、`verified:false`。0枚でも作る。

- **L より古い日の締め忘れは自動で預けない。** 要確認の一覧に出すだけ（取り込んだ過去の記録で残高が勝手に動くのを防ぐ）。
- 作成は通常の `save()` で行う。別タブが先に保存していれば、このタブは凍結されて書かない。id が固定なので、再読み込み・別タブ・同じJSONの取り込みを何回しても2件にならない。

### 4.3 新しい台を始めるとき
- 店舗とレート条件を選ぶと、貸出枚数・再プレイ1回の枚数・残高 A・本日の U と残り・手持ち H（今日の分）を表示する。
- 開始時の持ちメダルの初期値は H(口座, 今日)。本人が直せる。
- その口座に「要確認」の日があれば、先に締めのシートを出す（預けた枚数を入れる／預けていない・分からない＝settleSkip／あとで）。「あとで」を選んでも台は始められる。

### 4.4 今日の稼働を終える（最終預入）
- 稼働ノート（または台の終了後）に「今日の稼働を終える（貯メダルへ預ける）」を置く。口座ごとに：
  - 手持ち H を表示し、預けた枚数の入力欄の初期値を H にする
  - 入力 n が H より少なければ「行先未記録 H−n枚」と表示（保存はしない。計算で出す）
  - n が H より多ければ確認を出す（はいなら記録）
- 保存すると finalDeposit を作る（または直す）。同じ口座・同じ日に autoDeposit があれば `void` にする（記録は残す）。

### 4.5 直す・取り消す
- 口座ごとの履歴画面で、各記録の枚数を直す（`edits` に履歴を残す）・取り消す（`void`）・確認済みにする（autoDeposit のみ）。
- 台の終了持ちメダルを後から直したことで、その日の autoDeposit と H が食い違ったら、履歴に「自動預入 600枚／今の最終持ち 650枚　→ 合わせる」を出す（押すと amount を直す）。
- どうしてもずれたら「残高を合わせる」（balanceSet）で実数に合わせる。

## 5. D4 書き出し・取り込み・外部連携

### 5.1 rec のバックアップJSON
- 書き出す全ての箇所（「JSONを書き出す」「ダウンロード」「保存失敗時の書き出し」「別タブ競合時の書き出し」）に `ledger` を足す。`storageKey:"slot-tools-rec"` も足す（稼働日誌が出どころを判定できる）。
- 取り込み：
  - `ledger` が無いJSON（今までの書き出し）はそのまま読める。口座の記録は作らない（**無い履歴を作らない**）。
  - `ledger.events` は id で突き合わせる。同じ id・同じ中身 → 除外。同じ id・中身が違う → **手元を残し**、件数を「食い違い◯件（手元を残しました）」と表示。形が不正なもの → 取り込まずに件数を表示。
  - 実戦記録・店舗・簡易収支の取り込み規則は今までどおり。
  - 取り込み後に §4.2 の判定を1回走らせる（取り込んだ最新日だけが対象になり得る）。

### 5.2 振り返りノート用（kado-note 向け `toEnvelope`）
- **旧方式の台：出力を1バイトも変えない**（`payloadVer:"rec-3"`、`exchangeRate:s.lend` のまま）。
- **新方式の台**：
  - `payloadVer:"rec-4"`
  - `lendRate: cond.lend`、`exchangeRate: cond.exchPer1000`
  - `storeId: null` のまま（エンベロープの storeId は共通マスタのIDと決まっているため、rec のIDは入れない）、`storeName` は店舗名
  - `payload` に `recStoreId`、`recCondId`、`cond`（写し）を足す
  - `payout` の意味は変えない（`endMedal − startMedal − 再プレイ`＝この台の中の増減。台間の持ち越しは startMedal で引かれているので二重にならない）
- kado-note はこの値で `payout ÷ exchangeRate × 1000 − invest` を出す。rec は1枚あたり円（小数2桁）で計算するので、大きな差枚では数円ずれることがある（kado-note は閲覧用で合計に入らないため許容。仕様として記録する）。

### 5.3 稼働日誌（tools/nisshi）
- `recPlay()`：台に正しい `cond`（`exch > 0`）があれば、play の `cond` にその写しを入れる。これで日誌の収支は `units × exch − 現金` になり、rec と同じ値になる。`cond` がない台は今までどおり。
- `envelopePlay()` の `rec-` 分岐：`payload.cond` があれば同様に `cond` に入れる。
- 日誌内の `profit()` の写しも rec と同じ形（`cond` があれば交換で計算）に直す（`raw.recProfit` の値をそろえるため）。
- 店舗の取り込みは今までどおり（条件の新しい項目は残る）。
- すでに日誌に取り込まれている記録は、旧方式の台なので値は変わらない。

### 5.4 古い版のページが開いたままのとき
- 古い版も、知らない上位項目（`ledger`）と台の知らない項目は消さずに保存する作り（読み込んだ内容を丸ごと持ち回る）であることを確認済み。
- ただし古い版の `fixStores()` は条件の新項目を落とす。新しい版で保存した後に古いタブが保存しようとすると、世代番号で凍結されるので書き込まれない。公開は夜の反映（night-merge）で行い、反映前に「開いている実戦記録のページを読み込み直す」注意を出す。

## 6. D5 保存・復元の安全策

1. 保存は既存の `save()` だけを使う（1回の localStorage 書き込み＝cur・stores・entries・ledger・outbox が同時に確定）。
2. 読み込み時の形チェック：`ledger` は「無い」か「`ver:1` で `events` が配列」のどちらか。それ以外（壊れた形）は既存の「読めなかったデータ」扱い（自動保存を止めて元データを書き出せる状態）にする。
3. 1件ずつの形が不正な event は捨てずに `ledger.quarantine` に移し、計算に使わない。
4. 計算値（A・H・U）は保存しないので、保存の途中で落ちても「残高だけ進んだ」状態は起きない。
5. 複数タブ：既存の世代番号で後から保存しようとしたタブを凍結（新しく作る仕組みはない）。自動預入は id 固定で二重にならない。
6. IndexedDB の版・構造は変えない。旧データの移行処理はない（足りない項目の補完だけ）。

## v1.0.1 追補（シオンの裁定・2026-11-23）

1. C23：保存JSON全体の一致は仕様の誤り。C23 は「旧方式の台ごとの記録・収支合計・kado-note出力・日誌の値」の一致に限定する。既存テスト3本（rec-stock-replay／rec-log-order-past／rec-idb-sessions.e2e）は、比較の前に上位の ledger と storageKey の2キーだけを除いて比べる形に直す。他の期待値・比較は一切ゆるめない。e2e は後半のシナリオまで通常版・テスト版の両方で完走させる。
2. 手持ちH：その日に active な finalDeposit・settleSkip・autoDeposit のどれかがあり、それより後に終わった台がなければ H=0（autoDeposit を追加。C05 が正）。§4.5 の食い違い確認は H ではなく「その日の最後の台の endMedal」と autoDeposit の amount を比べる。
3. 取り消した自動預入：作り直さない（今の実装のまま）。§4.2 の5は「finalDeposit・settleSkip は active のもの、autoDeposit は void を含めて存在すれば何もしない」と読む。
4. 要確認の一覧：レビューの指摘どおり、balanceSet がある口座だけ、最初の balanceSet より後に終わった台がある日だけを対象にする。締めのシートは選んだ口座の分だけ出す。
5. save()：ミコトの変更を元に戻し、容量不足時の既存の回復処理をそのまま残す（記録が残ることを優先）。回復処理の途中で落ちた場合の不揃いは既存の限界として扱い、C13 は通常時の確認とする。

## v1.0.2 追補（2026-11-24 シオン裁定・独立検収の差し戻し対応）

1. 開始時の日付切替：店舗を選んだ日と「打ち始める」を押した日（JST）が違えば、自動預入の判定後に、自動入力のままの開始持ちメダルをその日の手持ちで入れ直し、表示を作り直して、台を始めずに確認を求める。本人が書き換えた値は残す。
2. 締めの開き直し：締めのシートの「手持ち」と「行先未記録」は、その日の最後の台の終了持ちメダルで出す。精算済みの日は記録済みの枚数を初期値にして「精算済み」と表示し、値を変えるときだけ確認して直す（edits に残す）。
3. 締めの条件：その口座の台が稼働中のとき、またはその日に終わった台がないときは、最終預入・締めを記録しない（画面と記録処理の両方で防ぐ）。
4. 過去の台の履歴修正：新方式の終了済みの台に履歴から足す記録の時刻は、その台の終了時刻とする。再プレイの上限・残高の確認は、その記録の日付の U で行う。旧方式の台は変えない。
5. 交換単価：1枚あたりの円は exch が正しければそれ、無ければ exchOf(exchPer1000) で補う。どちらも出せない条件は使わない。rec と日誌で同じ規則にする。取り込みで cond が不正な台は「形が不正」として取り込まない。

## v1.0.3 追補（2026-11-24 シオン裁定・独立再検収の差し戻し対応）

1. 記録の訂正：既にある口座の記録を直す・取り消す・確認済みにする・戻すときは、at・dayKey・type・id・createdAt を変えない。変えるのは amount・status・verified・note だけで、直した時刻は updatedAt と edits に残す。最新の残高合わせより前の記録を直しても残高は変わらない（画面にその旨を表示する）。
2. 終了持ちメダルの未確定：0 とみなさず「未確定」と表示する。手持ちは null とし、開始持ちメダルは自動入力しない。締めでは預入の記録はできるが、行先未記録と手持ち超過の確認は出さない。自動預入は作らない（§4.2 のまま）。
3. 再プレイの確認：上限はその再プレイの日の U で、残高はその再プレイの時刻が最新の残高合わせより後のときだけ確認する。
4. 精算済みの日には「預けていない・分からない」を記録しない（画面と記録処理の両方）。
5. 回帰防止として、操作をランダムに並べた残高の不変条件テスト（I1〜I6）を常設する。

## v1.0.4 追補（2026-11-24 シオン裁定・同じ日の再精算）

1. 締めの回：1日に何回でも締められる。ある回の締めは、その記録時刻より前に終わった台の手持ちを締める。id は1回目が final:口座:日／skip:口座:日、2回目以降は末尾に :2、:3… を付ける（番号は final・skip 共通）。
2. 手持ち H：その日の最後に終わった台が、その日の最新の有効な締め（finalDeposit・settleSkip・autoDeposit）より後に終わっていれば、その台の終了持ち（未確定なら null）。そうでなければ 0。
3. 締めのシート：まだ締めていない回があれば、前回の精算と「その後の台の手持ち」を表示し、新しい回として記録する。すべて締め済みなら、最新の回の枚数を直す（at は変えない）。過去の回は口座画面から直す。
4. 自動預入は、その日に締めの記録が1件でもあれば作らない（D2のまま）。まだ締めていない回がある日は要確認に出す。
5. 新方式の台で開始持ちが空欄なら、0枚で始めるか確認する。旧方式の台は変えない。
6. 開始時の日付の確認は、すべての確認を通った後、台を作る直前にも行う。

## v1.0.5 追補（2026-11-24 シオン裁定・締めの置き換えと追加）

1. 締めの記録（autoDeposit・finalDeposit・settleSkip）はすべて「回」を持つ。autoDeposit は常に1回目。
2. 締めのシートの記録は「追加」か「置き換え」のどちらか一方だけ。まだ締めていない回があるとき、または有効な締めが1件もないときは追加：既存の記録を変えず、その日の最大の回（取消済みを含む）＋1 の新しい回を、今日なら今の時刻、過去の日ならその日の最後の台の終了時刻で作る。それ以外は最新の有効な締めの置き換え：finalDeposit なら枚数だけを直し、settleSkip・autoDeposit ならその1件だけを void にして同じ回で作り直す（時刻は引き継ぐ）。
3. 置き換えで void にするのは対象の1件だけ。他の回の記録は変えない。
4. 取消済みの記録は active に戻さない。

## v1.0.6 追補（2026-11-24 シオン裁定・口座履歴の比較先）

1. 締めの記録（autoDeposit・finalDeposit）と比べる「その回の最終持ち」は、その記録の at までに終わった最後の台の終了持ちとする。種類で分けない。
2. 口座画面の「合わせる」と「行先未記録」は、この「その回の最終持ち」だけを使う。未確定、またはその時刻までに終わった台がなければ出さない。
3. その日全体の最後の台の終了持ちは、締めのシートで「まだ締めていない回」の手持ちを出すときだけ使う。

## v1.0.7 追補（2026-11-24 夢爽の実機確認からの改善）

1. 店舗を選ばずに「打ち始める」を押したとき、店名の欄が店舗設定の店名と一致すれば（NFKC・空白を除いて比較）、「店舗設定の店として始めますか？」と聞く。はいなら店舗を選んだ状態にして、台は始めずに確認を求める。いいえなら今まで通り店舗を選ばない台として始める。「店舗を選ばずに始める」を押した開始画面では聞かない。
2. 1つの店のスロットは1つのレートで運用する。店を選んだとき、スロットの条件が1つならそのまま決める。別のレートは別の店舗として登録する（店舗設定に案内を出す）。既に2つ以上の条件がある店は、今まで通り条件を選ぶ。
3. 確認済みの自動預入は「自動預入（確認済み）」と表示する。

## v1.0.8 追補（2026-11-25 夢爽の要望）

1. 新方式の台では、「再」のマスに、この台で再プレイした枚数（1行目）と今の貯メダル残高（2行目「貯 ◯枚」、未登録なら「貯 未登録」）を両方出す。旧方式の台は変えない。
2. 再プレイの画面に「店の残高と照合」を置く。店の残高を入れると、記録上の残高との一致・差を表示する。不一致・未登録のときだけ「履歴を見る」「店の残高に合わせる（balanceSet）」を出す。照合しただけでは何も保存しない。
3. 再プレイで使った枚数は差枚に含まれる（差枚＝今の持ち−開始の持ち−再プレイ。変更なし）。
