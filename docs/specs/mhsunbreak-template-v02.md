## 2. 記録の定義（夢爽決定）

- **発展先**: ブレイクゾーンが終わり、どのアイコンからクエストに発展したか
- **1回目**: AT終了後（朝一を含む）から最初のブレイクゾーン
- **2回目以降**: それ以降のブレイクゾーン（不屈の影響を分けるため）
- **すべて記録のみ。設定差の記載は無いので rank は持たせない**

### 発展先7種

ボタン表記は解析の名称（§9-64）。半角カナの略記は**テンプレ出力側だけ**で使う。

| id | ボタン表記 | テンプレ略記 | `▶︎` 前の半角スペース |
|---|---|---|---|
| `blue` | クエスト青 | `青ｽﾀｰﾄ` | 8 |
| `yellow` | クエスト黄 | `黄ｽﾀｰﾄ` | 8 |
| `raizex` | ライゼクス | `ﾗｲｾﾞｸｽ` | 8 |
| `serregios` | セルレギオス | `ｾﾙﾚｷﾞｵｽ` | 6 |

| `teo` | テオ・テスカトル | `ﾃｵﾃｽｶﾄﾙ` | 6 |

**略記とパディングは正本から読むこと**（正本を唯一の出典にする・§9-84）。
定義に書き写す場合も、正本と一致することを検証で固定する。

## 3【必須】state と導出

```js
const DEF={
  …既存…,
  bzT1:  Object.fromEntries(QUEST.map(c=>[c[0],0])),   // 1回目のテーブル回数
  bzT2:  Object.fromEntries(QUEST.map(c=>[c[0],0])),   // 2回目以降のテーブル回数
  questN:Object.fromEntries(QUEST.map(c=>[c[0],0]))    // クエスト成功回数（1回目・2回目以降の合算）
};
mergeKeys に 'bzT1','bzT2','questN' を追加
```

**クエスト成功率の分母は持たない。導出する**（§9-84・二重管理の禁止）。

```js
function questD(S,id){return n(S.bzT1,id)+n(S.bzT2,id);}   // 発展した回数＝テーブルの合計
function questHit(S,id){return n(S.questN,id);}
```

`normalizeState` で **`questN.<id>` を `questD(S,id)` 以下にクランプ**する（§9-87）。
既存の保存データ（この3キーが無い）を読んでもエラーにならないこと。

## 4【必須】BZタブの新設

`mhsunbreak-checker.html` の nav を**4ボタン**（`入力` / `示唆` / `BZ` / `カード`）にし、
`nav{grid-template-columns:repeat(4,1fr)}` にする。§9-67 の上限5つに収まる。
`pages` は `[pageInput, pageShisa, pageBZ, pageCard]`。

### 行の作り

セクションは2つ。見出しは **`1回目`** と **`2回目以降`**。各セクションに発展先7行。

- **青〜テオ・テスカトルの6行**: `［成功］［失敗］` の2ボタン
- **SUNBREAK RUSH の行**: `［＋］` の1ボタン（**成功として数える**）
- 行の表示: **`成功 n／回数 d`** と成功率%（`ctx.pct` と同じ `n/d xx%` の形でよい）。
  **設定別の数値は無いのでサブラベルは置かない**
- ボタンは高さ44px以上・横書き固定。`ricorico.js` の `.cycle-btn` のCSSを移植してよい

### 1タップで2つを同時に記録

engine の `data-bump-many`（カンマ区切りのパスを一括で ±1）を使う。

| ボタン | `data-bump-many` |
|---|---|
| 1回目の成功 | `bzT1.<id>,questN.<id>` |
| 1回目の失敗 | `bzT1.<id>`（**成功は増やさない**） |
| 1回目のAT ＋ | `bzT1.at,questN.at` |
| 2回目以降 | 同じ形で `bzT2.<id>` |

`data-label` は「1回目 クエスト青 成功」のように**グループ名と発展先名を残す**
（feed と取消の表示に出るため）。

**取消は engine の `bumpMany` が1操作としてまとめて戻す**（§9-96）。
**1タップ分（テーブルと成功率の両方）が戻ること**を検証で示すこと。

### 減算モード（§9-87・§9-72）

- `data-bump-many` は engine 側で「どれか1つでも0なら減算しない」を見ている
- **それに加えて、`失敗` ボタンは減算モードで `questD > questN` のときだけ有効**にする
  （`失敗` を減らすと分母だけ減るため、`n≦d` が壊れる）。
  無効時は `disabled aria-disabled="true"` を付ける
- ヒントに「訂正は減算モードで同じボタンを押します」の1文を入れる

### 説明（タブに1回・§9-51／折りたたみは engine 任せ・§9-97）

2つのセクションの下に**1回だけ**置く。`<details>` を手で組まない。

> ブレイクゾーン終了時に、どのアイコンからクエストへ発展したかを記録します。1回目はAT終了後（朝一を含む）最初のブレイクゾーン、2回目以降はそれ以外です。クエストの結果まで見てから［成功］［失敗］を押してください。記録のみで、設定差は判明していません。
