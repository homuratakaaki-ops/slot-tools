## 3. 保存データ（state）

```
{
  schemaVersion:1,
  start:{kind:'reset'|'bonusEnd'|'fail'|'unknown', failCount:0..5},   // §6-1
  custom:'off'|'on'|'unknown',                            // 終了画面カスタム
  counts:{cz:0, rb:0, bb:0, direct:0, bar:0, barDirect:0},
  groups:{endScreen:{...}, atEnd:{...}, roundRed:{...}, over:{...}, zorome:{...}, magiusCount:{...}, mumu:{...}, baffe:{...}},
  spans:[ { rows:[ ...row ], end:null|{t:'czmiss'|'rbmiss'|'bbend'|'atend'} } ],   // §5
  curPt:null|number,                                      // 進行中の周期の現在pt（任意入力）
  img:null, iconChoice:null
}
```
row の種類（spans[].rows[]）：
- 周期行 `{t:'cyc', k:1.., pt:100|200|300|400|500|600, r:'win'|'miss', magius:true|false}`
- 周期外当選 `{t:'out', k}`（ルーンドライブ・BAR直撃などで周期の途中にCZ／ボーナスへ。夢爽確認：CZ後・ボーナス後ともptはクリアされる）
- 引き戻し区間 `{t:'pull', r:'win'|'miss'}`（ボーナス・AT終了後66G。win なら次は AT、span は end:'atend' で閉じる）
- 示唆 `{t:'hint', c:<HINTキー>, k}`（k＝発生時の周期番号）

保存するのは入力そのもの。モード確率・pt候補・残り周期・「前回600pt」は保存しない（導出）。未知フィールドは捨てずに保持（§9-59・§9-108-4）。

## 5. 周期の進み方（状態遷移）

| 現在 | 操作 | 結果 |
|---|---|---|
| 開始 | 開始条件・カスタムを選ぶ | spans=[{rows:[],end:null}]、事前分布＝§6-1 |
| 周期k進行中 | 到達pt＋ハズレ | rows に cyc(k,pt,miss)、k+1 へ、curPt=null |
| 周期k進行中 | 到達pt＋当選 | rows に cyc(k,pt,win)、「CZ結果待ち」 |
| 周期k進行中 | 周期外当選 | rows に out(k)、「CZ／ボーナス結果待ち」 |
| CZ結果待ち | CZ失敗 | span.end='czmiss'、新span、事前＝事後×TRANS、k=1 |
| CZ結果待ち | CZ成功（決戦RB） | 「決戦結果待ち」 |
| CZ結果待ち | CZ成功（革命BB） | 「ボーナス終了待ち」 |
| CZ結果待ち（周期外当選から） | AT直撃（AT開始） | out 行に at:true、「AT終了待ち」（周期当選からの結果待ちには出さない） |
| 決戦結果待ち | 決戦失敗 | span.end='rbmiss'、新span、事前＝事後×TRANS、k=1 |
| 決戦結果待ち | 決戦成功→AT | 「AT終了待ち」 |
| ボーナス終了待ち | 革命BB終了（AT非当選） | span.end='bbend'、新span、事前＝PRIOR_RESET、k=1、引き戻し区間あり |
| ボーナス終了待ち | 革命BB終了（AT当選） | 「AT終了待ち」 |
| AT終了待ち | AT終了 | span.end='atend'、新span、事前＝PRIOR_RESET、k=1、引き戻し区間あり |
| 新span（引き戻し区間あり） | 引き戻し あり | rows に pull(win)、span.end='atend'、さらに新span（PRIOR_RESET） |
| 新span（引き戻し区間あり） | 引き戻し なし（66G経過） | rows に pull(miss)、以後は周期進行 |

- 周期番号 k＝その span 内の cyc 行数＋1（out 行は数えない）
- 「前回600pt」＝同じ span 内の直前の cyc 行の pt が600。span をまたいだら無効
- 開始条件が `reset`（設定変更後）のときだけ、その**最初の span** は天井周期を3とみなす（§6-3）。`bonusEnd`（ボーナス・AT終了後）は通常の天井。CZ失敗・終了契機で次の span に入ったら通常に戻る
- 周期の記録と設定示唆（終了画面など）は別のタブで独立に数える。周期タブの「CZ失敗」「決戦失敗」などの操作は spans だけを変え、counts/groups は変えない（二重計上を避ける。counts は入力タブで押す）
- 開始条件は途中で変えても spans（周期ログ）を消さない。start だけを書き換え、事前分布（§6-1）と最初の span の resetSpan を計算し直す

## 6. 計算（機種データ側の関数に集約。画面・カード・テンプレは同じ関数の結果を使う §9-84）

### 6-1 事前分布 `priorOf(S)`（最初の span）
- `start.kind==='reset'`（設定変更後）：PRIOR_RESET。最初の span は天井3周期（§5）
- `start.kind==='bonusEnd'`（ボーナス・AT終了後）：PRIOR_RESET。天井は通常
- `start.kind==='fail'`：PRIOR_RESET × TRANS^failCount（failCount=1..5。「それ以上」は5）。0回はボーナス・AT終了後（bonusEnd）と同じ
- `start.kind==='unknown'`：均等 25%
2つ目以降の span は §5 の end 種別で決まる（czmiss/rbmiss＝事後×TRANS、bbend/atend＝PRIOR_RESET）。

### 6-2 周期行の尤度 `rowLik(m, row, k, prev600, resetSpan)`
- pt：k=1 → PT1[pt][m]、k≥2 かつ prev600 → PT3、それ以外 → PT2。表に「—」なら 0。k≥2 の天国は 0
- 当否：q = hazard(m,k)。win → q、miss → 1−q
- hazard(m,k)：天井周期（A6／B3／C5／天国1、resetSpan なら全モード3）以上なら 1。それ以外は CYCLE[m][k] ／ (100 − Σ_{j<k} CYCLE[m][j])。表に値がない k は 0
- cycle 系示唆の制約：発生周期 kh から capWithin 周期目（kh+capWithin−1）に達した周期は hazard=1
- out 行：尤度に関与しない（その span を閉じるだけ）

### 6-3 事後 `posterior(S)`
span ごとに事前×Π尤度→正規化→ mode 制約を適用（exclude/only。onlyIfPullMiss は同 span に pull(miss) があるときだけ）→ 次 span の事前へ。表示は現在 span の事後。整数%、0.5%未満は「1%未満」、0 は表示しない。

### 6-4 次の到達pt候補 `nextPtDist(S)`
P(p)=Σ_m 事後[m]×PT表[p][m]（k・prev600 は現在の周期）。curPt が入力済みなら p>curPt だけ、pt 系示唆があれば p≤ptMax だけに絞って正規化。候補が0件なら「—」＋矛盾表示。

### 6-5 残り周期 `cycleCap(S)`
min(残るモードの天井−k+1、cycle 系示唆の残り、マギウス外れによる短縮、resetSpan なら 3−k+1)。マギウス外れ短縮＝同 span の `magius:true` かつ `r:'miss'` の行数だけ上限を1ずつ減らす（表示のみ・確率には使わない）。

### 6-6 この周期でCZになる参考% `winPctNow(S)`
Σ_m 事後[m]×hazard(m,k)。ラベルは必ず「参考」。

### 6-7 検算例（tests に固定）
開始 bonusEnd（69/25/5/1・通常の天井）→ 1周期目 200 miss → 2周期目 600 miss → 3周期目 400 miss：
- 1周期目：pt 200 → A.95 B.95 C.90 H.95、miss → A.86 B.95 C.89 H0 → 天国消滅
- 2周期目：prev600なし → PT2[600]：A.15 B.16 C— → C消滅、miss → hazard A 29/86=.337→.663、B 13/95=.137→.863
- 3周期目：prev600 → PT3[400]：A.47 B.17、miss → hazard B=1（天井3）→ B消滅、A 4/57=.070→.930
- 結果：A 100%。次の候補（4周期目・prev600なし）：PT2のA列 100:25／200:23／300:5／400:28／500:4／600:15。残り周期上限3（6−4+1）。参考% = 15/53 ≈ 28%
途中値（シオン検算 2026-10-28）：1周期目終了 A 67.97／B 27.20／C 4.83／天国 0。2周期目終了 A 64.27／B 35.73（A ∝ .6797×.15×.663、B ∝ .2720×.16×.863）。3周期目終了 A 100。4周期目の参考% 28.3。tests は小数第2位まで固定。

reset 開始の検算（tests に固定）：開始 reset（69/25/5/1・最初の span は天井3周期）→ 1周期目 200 miss → 2周期目 400 miss の時点で、3周期目は全モード当選確定（参考% 100）、残り周期の上限は1（3−3+1）。3周期目でハズレを記録した場合は全モードの尤度が0になり、矛盾表示になる。

## 12-1 参照表の折りたたみ（示唆タブ）
- `pageReference()` の出力全体を `<details><summary>参照表（設定別数値・振分表・示唆一覧）</summary>…</details>` で包む。既定は閉じる
- ジャンプボタン「参照」を押したときは details を開いてから移動する
- 設定推測区画（vv-bayes）は折りたたまない

## 12-2 現在ptをモード推測に反映
- 進行中の周期で `curPt` が入力されているとき、現在 span の事後に「未到達の尤度」を掛ける：
  `L_pt(m) = Σ_{p > curPt} PT表[p][m] / 100`（PT表は k・prev600 で選ぶ既存の `table()`。ピノの ptMax があれば p ≤ ptMax も課す）
- 掛ける場所は `spanPosterior` の末尾（最後の span かつ `phase==='cycle'|'pull'` のときだけ）。保存は変えない
- 例：3周期目・prev600なし・curPt=420 → C は 500/600 が「—」なので L_pt(C)=0 → C消去。A は (4+15)/100=0.19、B は (14+16)/100=0.30
- curPt が全モードで L_pt=0（例：1周期目で curPt≥200）→ 既存の矛盾表示「到達pt候補がありません」。モード確率は curPt を外して計算し、警告だけ出す（ピノ示唆の矛盾と同じ扱い）
- `nextPtDist` は従来どおり（この更新で事後も変わるので、候補の%も自然に変わる）

## 12-3 当選までの見込み（周期タブ上段・参考）
「当選」＝CZ突入（周期到達→前兆→CZ）。ボーナス当選・AT当選は含めない。

### 計算 `untilWin(S)`（機種データ側の1関数。シミュレーションではなく全経路の列挙）
入力：事後 p[m]（12-2 反映後）、現在周期 k、curPt（未入力は0）、prev600、resetSpan、有効な示唆（cycle 系の cap、pt 系の ptMax は当該周期のみ）。
各モード m について、状態 (k, prev600, isFirst) から再帰で「当選までの追加pt」の分布を作る：
```
dist(m, k, prev600, isFirst):
  T = table(k, prev600)、候補 = {p : T[p][m]>0}、isFirst なら p>curPt（と ptMax）に限る
  候補が空 → このモードは寄与なし（事後が0のはず）
  a[p] = T[p][m] / Σ候補 T[・][m]
  cost[p] = isFirst ? p − curPt : p
  q = hazard(m, k, resetSpan, hints)
  for p in 候補:
    当選 : 確率 a[p]·q, 追加pt = cost[p], 周期数 +1
    ハズレ: 確率 a[p]·(1−q) → dist(m, k+1, p===600, false) の各要素に cost[p] と 周期数1 を足す
```
hazard が 1 になる周期（天井・reset時3・cycle 示唆の cap）で必ず止まる。全モードの分布を p[m] で重み付けして合算。

### 出す値
- 平均：`avgPt = Σ 確率×pt`、`avgCycles = Σ 確率×周期数`
- 分位：累積確率が初めて 50%・80% 以上になる pt（pt は100刻みの合計なので「○pt以内」と言える）
- G目安：`avgPt / 3`（出典「平均300pt＝約100G」の比。小数は切り捨て、「約」を付ける）
- 1行目：`当選まで（参考）：平均 あと約420pt（約140G）`
- 2行目：`50%で300pt以内／80%で700pt以内／平均 あと1.4周期`
- 事後が全部0（矛盾）のときは「—」。表示はすべて「参考」ラベル付き。期待値・収支・推奨には言及しない（§9-60）

### 検算例（tests に固定）
- 開始 bonusEnd、記録なし（1周期目・curPt 0）：各モードの1周期目は 100/200 のみ。A：200pt 95%／100pt 5%、q1=.14 → 当選14%、ハズレ86%で2周期目へ（PT2、q2=29/86）… と展開。tests は小数第1位まで固定（実装側で算出した値をシオンが別計算で照合）
- 開始 bonusEnd、1周期目 200 ハズレ、2周期目 600 ハズレ、3周期目 curPt 420：C消去、A/B の事後は 12-2 で再計算。3周期目の候補は A：500(4)/600(15)、B：500(14)/600(16)（prev600 なので本来 PT3 だが PT3 に 500/600 は無い → 候補なし！）

  → **注意**：前回600ptの次周期は PT3（400以下のみ）。curPt=420 なら全モードで候補なし＝「前回600ptなら今周期は400pt以内のはず」という矛盾。これは正しい挙動（記録ミスの検出）。tests ではこのケースで矛盾表示になることを固定し、例は curPt=250 に変えて A：300(6)/400(47)、B：300(31)/400(17) で検算する
- reset 開始、2周期ハズレ、3周期目：hazard=1 なので「平均あと○pt＝今周期の候補の平均−curPt、周期数1.0、50%/80%とも今周期内」
