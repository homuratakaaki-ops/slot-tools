## 1. 目的と対象（Step 0）

### 目的
- rec で東京喰種を記録 → 終了 → 稼働日誌に取り込む、だけで、分析画面に東京喰種の集計が出る
- 条件（期間・店舗・着席時の状況・開始時CZスルー・前回状況）で絞り込んで、同じ指標を出し直せる
- 共通の集計部分と「機種ごとの定義」を分け、将来は定義を足すだけで他機種に広げられる形にする

### 二層構造での置き場所
| 層 | 置くもの |
|---|---|
| 記録（rec） | 一次データ：着席項目（前回状況の補足を含む）、通常時に戻った時点のG数、既存のCZ・AT・有馬イベント |
| 振り返り（日誌） | 集計（保存しない・表示のたびに計算）、日誌側の補足・訂正（注釈）、旧手集計の確定値 |

### 対象（今回やる）
1. rec：東京喰種の着席項目に「前回CZの当選契機・当選時のG数（データカウンタ・液晶）・規定G数」「前回ATの結果（駆け抜け／駆け抜け以外）」を追加（前回の当選に連動して出る・任意）
1-2. rec：台の中のCZ当選（レミニセンス・大喰いの利世）で契機「規定G数」を選んだとき、規定G数を電卓で入れられる（任意）
2. rec：CZ・AT・有馬などが終わって通常時に戻った時点のG数をログに保存
3. rec：打ち始めた後でも着席項目を直せるようにする
4. rec：東京喰種だけ、書き出しJSONに着席項目と構造化イベントを追加で含める
5. 日誌：共通の集計部品（新規ファイル）＋東京喰種の定義
6. 日誌：分析画面に東京喰種の集計と条件の絞り込み、台の詳細に「その台の集計」と「前回状況の補足・訂正」
7. 日誌：旧111件の確定値の読み込みと合算、sessionIdでの重複防止
8. 回帰検査：保存・取り込み・再取り込み・バックアップ往復・他機種・既存の円収支

### 除外（今回やらない）
- 東京喰種以外の機種での集計の有効化、からくりサーカス2・ハイビリターン30等の定義追加
- 汎用 rec・他機種の画面の変更、既存の円収支・店舗・貯メダル・再プレイ・設定判別・日記・タグの仕様変更
- CZ失敗後のG数の初期値の変更（東京喰種第3弾で反映済み）
- 期待値の予測・狙い目の自動判定・損益分岐AT到達率（11/20案の5）
- モードの予想そのもの（「次は○○モード」と表示すること）。今回は予想に使う集計（CZごとの表・失敗の次）まで
- スルー段階ごとの到達率など、CZごとの表・失敗の次以外の区間単位の分析
- クラウド同期・自動同期・サーバー
- 個人の実戦データ（111件の原本）をリポジトリや公開ページに置くこと、原本の自動書き換え
- 本件と関係のない整理・書き換え

## 3. 流れ（時系列の一文リスト）

【入力】＝夢爽が入れる／【自動】＝ツールがやる

**rec（記録）**
1. 着席：前回の当選を選ぶ【入力・任意】
   - 「CZ失敗」→ 前回CZの当選契機、当選時のG数（データカウンタ・液晶）、契機が規定G数なら規定G数（電卓）の欄が出る【入力・任意・どれか1つだけでも可】
   - 「AT終了」→ 前回ATの結果（駆け抜け／駆け抜け以外）が出る【入力・任意】
   - 「有馬失敗」「不明」→ 追加の欄なし
2. 通常時を回す。CZ・EP・ATの当選・成否・有馬は既存どおり【入力】。CZ当選で契機「規定G数」を選んだら規定G数（電卓・任意）【入力・新規】。当選時のG数は今までどおり自動で残る
3. CZ・AT・有馬が終わり通常時に戻る：今のG数（既存の欄・初期値あり）【入力】→ **その値をログに保存**【自動・新規】
4. 打っている途中や終了後に、着席項目を直せる【入力・新規】
5. ヤメ（既存）。書き出しJSONには、着席項目と構造化イベントも入る（東京喰種のみ）【自動・新規】

**日誌（振り返り）**
6. 「このブラウザの記録を取り込む」（既存）→ 終わった台が入る。再取り込みで更新される（既存）
7. 分析で機種「東京喰種」を選ぶ → 東京喰種の集計が出る【自動】
8. 絞り込み（期間・店・着席時の状況・開始時CZスルー・前回状況・前回CZの契機・規定G数・当選時G数の範囲・前回AT結果）を変える → 出し直す【自動】
8-2. 「CZごと」の表：CZ当選を契機・規定G数別に並べ、成功率と、失敗した後の次の当選（契機・規定G数・液晶G）を見る【自動】
9. 台の詳細 → その台の集計を見る／前回状況を補足・訂正する（rec は書き換えない）【入力・任意】
10. 設定 → 旧手集計の確定値（ネネの統合JSON）を読み込む → 既存の台と sessionId で突き合わせ【入力1回＋自動】

戻りの流れ：rec で記録を取り消し・直す → 日誌で再取り込み → 集計が追従。日誌の補足・訂正は残る。

## 4. 状態遷移表（集計で使う「通常時の区間」の区切り）

集計は rec のログを頭から読み、次の2状態で区切ります。

| 今の状態 | 出来事（ログ） | 次の状態 | 集計でやること |
|---|---|---|---|
| （開始） | 着席 | 通常時 | 区間の始点＝開始実G |
| 通常時 | CZ当選（レミ／利世） | 当選中 | 区間の終点＝当選時の実G。区間Gを加算。CZ当選＋1 |
| 通常時 | EP当選 | 当選中 | 区間を閉じる。EP当選＋1 |
| 通常時 | AT当選（直撃・天井・引き戻し等） | 当選中 | 区間を閉じる。AT初当たり＋1（契機別） |
| 通常時 | G数を直した（gFix） | 通常時 | 区間Gには足さない。「補正あり」印（Q2） |
| 当選中 | CZ成功→AT | 当選中 | CZ成功＋1、AT初当たり＋1（契機＝そのCZ） |
| 当選中 | CZ失敗 | 通常時 | CZ失敗＋1。区間の始点＝**保存された戻りG**（R2） |
| 当選中 | EP終了→AT | 当選中 | AT初当たり＋1（契機＝EP後）。EPとATで二重に数えない |
| 当選中 | AT終了（通常時へ） | 通常時 | 区間の始点＝戻りG |
| 当選中 | AT終了→有馬ジャッジメント | 当選中 | 有馬＋1 |
| 当選中 | 有馬成功→死神→AT | 当選中 | 有馬成功＋1。このATは**初当たりに数えない** |
| 当選中 | 有馬失敗 | 通常時 | 有馬失敗＋1。区間の始点＝戻りG（実6なら、次の当選G−6） |
| 通常時／当選中 | ヤメ | （終了） | 通常時なら区間の終点＝終了実G。当選中のヤメは成否「不明」 |

- 使うG数は**データカウンタ（実G）**。液晶Gは条件（前回CZの液晶G）にだけ使う
- 区間Gがマイナスになったら、その台は「G数の不整合」として通常Gの合計から外し、件数を表示する

## 5. 引き継ぎ・リセット規則

| 値 | 規則 |
|---|---|
| 着席項目（前回状況など） | 1台（セッション）に1つ。台をまたいで引き継がない |
| 前回CZの契機・G数・規定G数 | 「前回の当選＝CZ失敗」のときだけ有効。前回の当選を別のものに変えたら**保存時に消す**（使われない値を残さない）。規定G数は契機＝規定G数のときだけ |
| 台の中のCZの規定G数 | そのCZ当選の行に1つ。契機を規定G数以外に直したら消す。取り消しで一緒に消える |
| 前回ATの結果 | 「前回の当選＝AT終了」のときだけ有効。同上 |
| 戻りG | 通常時に戻る操作ごとに1つ。取り消しで一緒に消える（既存の op 単位の取り消しに乗る） |
| 日誌の補足・訂正 | 日誌の台に付く。再取り込みでも消えない。rec の値より優先 |
| 集計値 | どこにも保存しない。表示のたびに計算（再取り込み・訂正に自動で追従） |

## 7. 表示値ごとの計算式と入力元

共通の集計部品（新規 `js/play-stats.js`、仮名）で1関数ずつに集約します。

| 表示値 | 計算式 | 入力元 | 出せないとき |
|---|---|---|---|
| 通常時G | 各区間の（終点実G − 始点実G）の合計 | 開始実G・各当選の実G・`toG`・終了実G | 始点不明の区間は既定値で推定し「推定あり」件数を表示 |
| CZ当選確率（合算・レミ・利世） | 合計通常G ÷ 合計CZ当選回数 | 同上＋CZ当選 | 回数0 →「—」 |
| CZ成功率（合算・種別） | 成功 ÷（成功＋失敗）。不明は分母外で件数を併記 | CZ終了行の成否 | 判明0 →「—」 |
| AT初当たり確率 | 合計通常G ÷ AT初当たり回数（死神後を除く） | AT当選行と契機 | 回数0 →「—」 |
| AT契機別（重ならない分類） | 回数。レミ経由／利世経由／EP経由／直撃（規定G数・レア役）／天井／引き戻し／不明。「有馬失敗後のCZ」は内訳の印 | 契機（`trig`）・`afterMark` | — |
| EP当選 | 回数 | EP当選行 | — |
| 有馬ジャッジメント | 成功 ÷（成功＋失敗）。CZには数えない | 有馬の当選・終了行 | — |
| 実差枚（1台） | 終了持 − 開始持 − 再プレイ − round(現金投資 ÷ 1000 × 貸枚数) | rec のお金の記録 | 終了持なし、または現金ありで貸枚数なし →「未確定」で合計から外し件数表示 |
| 合計・平均差枚 | 合計 ÷ 確定台数 | 同上 | 確定0 →「—」 |
| 勝率 | プラスの台 ÷ 確定台数。±0は勝ちに含めず母数に含める | 同上 | — |

| CZごとの表（新規） | CZ当選1回ずつを「種別・契機・規定G数・当選時の液晶G」で分けて、当選回数・成功・失敗・不明 | CZ当選行（`trig`・`kiteiG`・`lcdG`）と成否 | 件数0の行は出さない |
| 失敗の次（新規） | CZ失敗の次の当選（同じ台の中）の種別・契機・規定G数・液晶G。台の中に次がなければ「ヤメ（○G）」 | 同上。着席前の分は R1 の前回CZ | — |

- 確率は「台ごとの比率の平均」ではなく、**合計G ÷ 合計回数**
- 着席条件での絞り込みは**台（セッション）単位**。その台の全部の数値がその条件に入る
- CZごとの表・失敗の次は**CZ単位**。台単位の数字と混ぜない（画面でも分けて出す）
- 値の優先順位：**11/27までの111件（確定値にある sessionId）はネネの確定値、それより後の台は rec から自動**。そのうえで、日誌の前回状況の訂正は自動の台にだけ効く
- 111件は契機・規定G数が揃っていないため、「CZごとの表」「前回CZの契機」の絞り込みでは「不明」に入る（統合JSONに契機があれば使う）
- 対象にならない台（汎用で記録した旧「東京喰種」で確定値もないもの）は数えず、「集計の対象外 ◯件」と出す
- 機種の判定：`machineDef`（rec 定義キー）が tokyoghoul の台を対象。旧名「東京喰種」は machine master の `s0001` で同じ機種として扱う

### 共通化の形（将来の他機種展開）

| 共通部分（全機種で同じ） | 機種ごとの定義（今回は東京喰種のみ） |
|---|---|
| 台の識別（sessionId）・重複除外 | どの当選がCZ／EP／AT／その他か、CZの種類 |
| 通常時の区間の切り方（始点・終点・`toG`） | 初当たりに数えない契機（死神後） |
| 回数・分子分母の合計、「—」と不明件数の出し方 | 契機の分類表 |
| 実差枚・平均・勝率 | 条件に使う着席項目とその表示名 |
| 期間・店の絞り込み、注釈・確定値の優先順位 | 有馬のような「CZに数えない上位抽選」 |

- 有効にする機種の一覧を部品の中に持ち、今回は東京喰種だけを入れる。一覧にない機種は今までどおり何も出ない（推定表示もしない）
- CZのない機種、通常G以外を分母にする機種は、その機種の定義のときに個別に決める（今回は作らない）
- 注意：機種の分類情報が rec の定義（index.html 内）と集計の定義（新ファイル）の2か所になる。rec の定義を共通ファイルへ出すときに1つにまとめる（今回はやらない・IDEAS.md に記録）
