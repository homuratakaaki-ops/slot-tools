## 2. 段階の切り方

器の変更が大きいので、4段に分けます。各段の終わりに §13 の通し操作で確認します。

### 第1段：定義の書き換え＋器の小変更（壊れにくい）

- C02 劇場ジャッジ失敗→女神（failTo、終了画面なし）
- C05 神 失敗→通常AT（failTo）、成功→上位AT
- 前兆を3段階に（煽り／前兆／前兆ステージ）。煽りで「発展せず」の出口。各段階は任意
- 当選シートに「告知された場所」（任意）
- 通常時の幕間失敗で運命盤回数・🍉を持ち越す（keepParCount）
- 上位ATに ED サブ状態
- ED終了時に1枚絵・ボイスを任意で聞く
- AT終了シートに「BET前に終了画面・ボイスを確認」の注意
- 「運命の一劇」goto ボタンを廃止（第2段の権利に置き換えるまで、AT終了→一劇は手動で当選ボタンから）

通し操作：§13 の 1, 3, 4, 5, 8

### 第2段：一劇の権利、AT中の神

- ticket フラグ。激情ジャッジ「成功」3回目で自動付与＋手動トグル
- AT終了の行き先：権利あり→一劇／なし→幕間
- AT中「機械仕掛けの神」ボタン。失敗で元のATに戻る（ステージ・権利・復活回数を保持）
- 取り消しに ticket を含める

通し操作：§13 の 6, 7, 9

### 第3段：報酬待ち、🍉の内訳、報酬変更

- pendingReward。ミッション成功→待ち。バッジ→タップで当選（契機：運命盤）
- CZ／AT終了で pendingReward を消さない
- 🍉を場面別に記録（通常中／ミッション中／報酬待ち中）
- 「報酬変更（昇格）」操作と履歴
- 取り消しに pendingReward と🍉内訳を含める

通し操作：§13 の 2, 10

### 第4段：モード示唆の履歴

- modeHints[] と modeEra
- CZ終了画面14種に示唆と有効区間を定義
- 表示：今の区間に有効な示唆をバッジに並べる
- 幕間失敗・劇場→女神で区間を進めない
- 取り消しに含める

通し操作：§13 の 11

## 3. 既存データへの影響

- 保存済みセッションの events は変えない。新しい状態（ticket / pendingReward / modeHints / modeEra / 🍉の場面）は fixSession で既定値を補う
- 🍉の内訳は、旧データでは全部「通常中」として扱う
- kado-note へのエンベロープは payloadVer を "rec-3" に上げる。logs の形は変えない
- チェッカー送信（toChecker）は、神失敗→AT と SHOW TIME後を「通常時からのAT当選」に含めるかを第2段で決める（U12）

## 4. 量産への持ち越し（v0.1 末尾への回答）

v0.1 が求める表現力のうち、器に汎用の仕組みとして入れるもの：

| 求められるもの | 器の仕組み |
|---|---|
| 主状態と並行状態 | mode + parallel[]（現状あり） |
| 未発動の報酬 | pendingReward（第3段） |
| 入口別の戻り先 | hits[].czEnd.failTo / successToAt（第1段で拡張） |
| 入口別のG数 | keepG と終了時入力（現状あり） |
| 入口別の記録項目 | hits[].grid / atStart.skipTriggers（現状あり） |
| 複数区間にまたがる示唆 | modeHints + modeEra + span（第4段） |
| 権利の持ち越し | ticket（第2段） |
| CZの中から別の当選へ、失敗で元に戻る | hits[].returnTo（第2段） |

からくり2固有のリセット条件（🍉の仮ルールなど）は定義側に置き、器には固定しない。
