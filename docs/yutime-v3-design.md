# 遊タイム実戦ツール v3 設計図

作成: シオン

依頼者: 夢爽

実装対象: `yutime-v3.html`
公開形態: 限定公開。TOPページ・既存ページからリンクしない。URL直打ちのみ。

## 0. 開発方針

- v3 は現行 v2 とデータを共有しない。
- localStorage キーは `ytv3:` prefix に完全分離する。
- 現行 `yutime-record.html` は残置し、v3 安定後に移行ツールを別途検討する。
- SPA 構成は現行と同じく、単一 HTML・インライン JS とする。
- スキーマ変更時の容量予算記録ルールを v3 にも適用する。

## 1. 実戦フロー

```text
[店選択] -> [フロアマップ（台を探す）] -> 台番タップ
                              -> [打ち始めウィザード] -> セッション開始
                              -> [稼働中画面]
                              -> [当選ウィザード]
                             -> [ヤメ入力] -> セッション確定 -> マップへ戻る
```

- 全ウィザードは「次へ」で進む直列形式。
- 全項目スキップ可能。
- スキップ項目は `null` 保存する。
- 未入力項目があるセッションは「未入力あり」バッジを表示し、台帳の「記録の修正」から後で補完できる。

## 2. データモデル

### 2.1 Store

```json
{
  "id": "string",
  "name": "string",
  "isPersonal": true,
  "lendRate": 4,
  "exchangeBalls": 25,
  "netBallsPerWin": 1400,
  "createdAt": "ISO8601"
}
```

- `lendRate` は貸玉レート（円/玉）。現金投資の玉換算に使う。
- `exchangeBalls` は交換玉数（100円あたり）。25玉交換なら25、28玉交換なら28を入れる。
- 換算収支は `差玉 * (100 / exchangeBalls)` で計算する。
- `netBallsPerWin` は期待値計算用の1回あたり純増玉。既定は1400で、技術介入に合わせて手動調整する。実測出玉からの自動切替は行わない。
- 既存店は読み込み時に `lendRate: 4`、`exchangeBalls: 25`、`netBallsPerWin: 1400` を補完する。旧 `exchangeRate` がある場合は `100 / exchangeRate` で `exchangeBalls` へ自動変換する。

### 2.2 MapLayout

店に 1 つ持つ。B1 以降は島ビルダーで入力し、構造化データとして保存する。

```json
{
  "islands": [
    {
      "left": { "from": 101, "to": 105 },
      "right": { "from": 199, "to": 195 },
      "excluded": ["104"]
    }
  ],
  "updatedAt": "ISO8601",
  "errors": []
}
```

- `left` は左列、`right` は右列。右列が空欄の場合は `null` として片面島を表す。
- `from` と `to` は昇順・降順どちらでもよい。
- `excluded` は存在しない台番の一覧。プレビュー上の台番をタップして除外/復帰する。
- 旧テキスト定義 `{ source: "100-104 | 199-195" }` は読み込み時に `islands` へ自動変換する。
- 旧テキストに歯抜け指定がある場合は、先頭から末尾までの範囲に展開し、存在しない中間台を `excluded` に入れて台番構成を維持する。
- 重複台番など、読めても危険な状態は警告表示する。

### 2.3 Machine

```json
{
  "id": "string",
  "storeId": "string",
  "daiNo": "string",
  "modelName": "string",
  "roundBalls": null,
  "memo": "",
  "presetId": "",
  "evSupported": false
}
```

- フロアマップから台番だけの Machine を自動生成する。
- 機種名、1R 玉数、台メモ（釘・癖など）は後付け編集できる。
- B1 で `payoutType` は廃止。旧データに存在する場合も読み込み時に保持しない。
- B2 で機種プリセットを追加。B5 以降は `MACHINE_PRESETS = [{ id, name, roundBalls, standardRounds, standardPayout, evSupported, spec }]` の定数テーブルで管理する。
- 初期プリセットは P大海物語5スペシャル のみ。選択時は機種名、1R玉数 140、期待値対応フラグを自動セットする。
- P大海物語5スペシャル の標準出玉は `standardRounds: 10`、`standardPayout: 1400` とする。
- その他（自由入力）では機種名と 1R玉数を手入力し、期待値対応フラグは false とする。

### 2.5 DailyState

台×日付で、朝一状態と閉店チェック値を保存する。

```json
{
  "dailyState": {
    "machineId": {
      "YYYY-MM-DD": {
        "date": "YYYY-MM-DD",
        "ramClear": "cleared | retained",
        "closingSpin": 575
      }
    }
  }
}
```

- `ramClear` は当日だけ有効。`cleared` はラムクリ確認済み、`retained` は据え置き確認済み。翌日は未確認に戻す。
- `closingSpin` は閉店チェックで入力する閉店時点の回転数。翌日の宵越し判断にのみ使う。2日以上前の値は判定・マップ表示に使わない。
- 自分のセッション `endSpin` は履歴表示には使うが、宵越し期待値の根拠には使わない。

## 3. 保存キー仕様

v3 は以下の localStorage キーのみを使用する。

| key | 用途 | 書き込みタイミング | データ形式 |
|---|---|---|---|
| `ytv3:data` | v3 本体データ | 店追加、マップ保存、台情報保存、セッション開始、投資追記、投資履歴削除、遊タイム突入、当選保存、終了保存、記録の修正保存 | JSON.stringify された v3 全体データ |
| `ytv3:premigrate` | 将来のスキーマ変更時に、旧 schema の raw データを退避する | 読み込み時、保存済み `version` が実装中の `SCHEMA_VERSION` と異なり、かつ `ytv3:premigrate` が未作成の場合。B1 では schema 1 から 2、B2 では schema 2 から 3、B3 では schema 3 から 4、B4 では schema 4 から 5、B5 では schema 5 から 6、Phase 4差し戻し1では schema 10 から 11、B10では schema 11 から 12、B20では schema 12 から 13 への更新時に作成対象となる | 変更前の `ytv3:data` raw 文字列 |
| `ytv3:backup:latest` | 通常保存前の直近バックアップ | `persist()` 実行時、既存の `ytv3:data` がある場合に、新しい `ytv3:data` を書く直前 | 直前の `ytv3:data` raw 文字列 |
| `ytv3:carryover` | 次セッションへ引き継ぐ持ち玉・残高の待機状態 | 終了サマリの「この持ち玉で次の台へ」押下時に作成。打ち始めウィザード確定時、破棄ボタン押下時、日付が変わった読み込み時に削除 | `{ storeId, sourceSessionId, sourceMachineId, sourceDaiNo, date, mochidama, credit, saipurei, createdAt }` の JSON 文字列 |
| `ytv3:corrupt:<ISO日時>` | 破損した `ytv3:data` の退避 | `loadData()` で `ytv3:data` が JSON として読めなかった場合に作成。自動削除しない | 破損していた `ytv3:data` raw 文字列 |
| `ytv3:running:sticky` | 稼働中ヘッダの固定表示設定 | 固定ON/OFF切替時 | `"on"` または `"off"` |

### 3.1 容量予算記録

`data.meta` に以下を持つ。

- `lastSaveChars`: 直近保存時の `JSON.stringify(data).length`
- `sampleSessionChars`: Session 1 件の `JSON.stringify(session).length`
- `sampleMachineChars`: Machine 1 件の `JSON.stringify(machine).length`
- `mapLayoutChars`: 現在の MapLayout 1 件の `JSON.stringify(layout).length`
- `schemaBudgetNote`: 容量予算の注記

実装上、画面下部にも保存キー、現在保存 chars、フロアマップ chars、台データ 1 件 chars、セッション 1 件 chars、引き継ぎ chars を表示する。

B5 実測値:

- schema 6 Store 1 件サンプル（`lendRate`、`exchangeRate`あり）: 122 chars
- schema 6 空フロアマップ: 14 chars (`{"islands":[]}`)
- schema 6 台データ 1 件サンプル: 151 chars
- schema 6 セッション 1 件サンプル（`carriedFromSessionId`、normal/yutime 投資各1件、`yutimeEnterTime`あり）: 699 chars
- `ytv3:carryover` 1 件サンプル: 203 chars

## 4. 派生値

保存せず表示時に計算する。

- 投資レコードは `phase: "normal" | "yutime"` を持つ。既存の `phase` なし投資は読み込み時に `normal` として扱う。
- 遊タイム突入後に追記された投資は `yutime` phase として保存する。
- 現金投資の玉換算は `投資金額 / store.lendRate`。
- 通常消費玉 = 開始持ち玉 + 通常 phase 投資玉換算 - 遊タイム突入玉。突入なしの場合は当選時残り玉を引く。
- 非パーソナル店、遊タイム突入玉未入力、または当選時残り玉未入力の場合は投入玉ベースにフォールバックする。
- `startMochidama === null` のセッションは回転率を算出せず、台の参考回転率集計から除外する。持ち玉なし現金スタートは `0` を入力する。
- 当選時残り玉が未入力で、プリセット機種かつ `hitCount` と `endTotalBalls` がある場合は標準出玉で概算する。
- 概算獲得出玉 = `hitCount * standardPayout`。ただし `totalRounds` が入力済みなら `roundBalls * totalRounds` を優先する。
- 概算残り玉 = `endTotalBalls - 概算獲得出玉`。負数は 0 にクリップする。
- 概算を使った回転率・獲得出玉には「概算」を表示する。台の参考回転率には概算セッションも含め、台詳細で「概算◯件を含む」と注記する。
- セッション回転率 = 通常回転数 / 通常消費玉 * 250
- 台の参考回転率 = セッション群の通常回転数合計 / 通常消費玉合計 * 250
- 遊タイム玉減り = 遊タイム突入玉 + yutime phase 投資玉換算 - 当選時玉数。当たらず終了の場合は終了時玉数を引く。
- 差玉 = 終了時玉数 - (開始持ち玉 + 全投資玉換算) + 残保留増減。
- 換算収支 = 差玉 * `(100 / store.exchangeBalls)`。
- R数ベース出玉 = `roundBalls * totalRounds`
- 1回あたりR数ベース平均出玉 = `roundBalls * totalRounds / hitCount`

## 4.1 自動ラベル

セッションの日付から以下を都度計算する。保存はしない。

- 曜日: 月曜日から日曜日
- つく日: 日付の一の位から `1のつく日` から `0のつく日`
- ゾロ目日: 11日、22日

手動のイベントメモは店独自イベントだけを登録する。フィルタでは自動ラベルと手動イベントメモを合わせて判定する。

## 5.3 B3 操作更新

- ウィザードは画面上部寄せとし、ボタン順を「次へ」「スキップ」「戻る」にする。
- ウィザードの数値入力では Enter/確定キーを「次へ」として扱う。textarea は Ctrl+Enter / Cmd+Enter のみ次へにする。
- 稼働中画面に `+500円`、`+125玉` のワンタップ投資ボタンを置く。直接入力も残す。
- 投資履歴は追記単位で表示し、各行を削除できる。削除時はカード残高・再プレ残りも再計算される。
- 開始時のカード残高・再プレ残りが未入力の場合は「未入力」と表示し、残高連動は行わない。
- 遊タイム突入時は `yutimeEnterTime` を保存し、その後の投資は遊タイム中投資として記録する。
- ヤメ入力の最初に「大当たりあり」「当たらず終了（遊タイム抜け含む）」を選ぶ。当たらず終了は `hitCount = 0` として保存する。
- セッション確定後はサマリカードを表示し、「台帳で見る」から当該記録へ移動できる。

## 5.4 B4 持ち玉引き継ぎ

- 引き継ぎは終了サマリの「この持ち玉で次の台へ」を押した時だけ発生する。
- 引き継ぎ待機状態は `ytv3:carryover` に保存し、同日内のページ再読み込みでも残す。
- 日付が変わった `ytv3:carryover` は読み込み時に削除する。日またぎ引き継ぎはスコープ外。
- フロアマップ上部に「引き継ぎ中」バナーを表示し、持ち玉、カード残、再プレ残、元台番を示す。
- 「引き継ぎを破棄」で `ytv3:carryover` を削除する。
- 打ち始めウィザードでは、持ち玉、カード残高、再プレ残りをプリセットする。元が未入力だった項目は空欄のままにする。
- 引き継ぎ値はウィザード内で手修正できる。
- ウィザード確定時に `carriedFromSessionId` を保存し、`ytv3:carryover` を削除する。
- 台帳には `carriedFromSessionId` をもとに「⇐ 台◯◯から続き」を表示する。

## 5.5 B5 デバッグ修正

- `ytv3:data` が破損 JSON の場合は、初期状態へフォールバックする前に `ytv3:corrupt:<ISO日時>` へ raw 文字列を退避する。
- 破損退避時は起動時に「保存データが読み取れなかったため退避しました」と表示し、フッターに「破損退避データあり」を出す。
- `persist()` は `lastSaveChars` を計上してから 1 回の `localStorage.setItem()` で保存する。
- 店ごとに貸玉レートと交換玉数を持つ。店追加・店設定から編集できる。
- ウィザードの「戻る」は、現在ステップの入力値を保存してから前ステップへ戻る。

## 5.6 Phase 3 フロアマップへのデータ表示

- フロアマップの台番ボタンは、台番、参考回転率、前日ヤメ回転数を縦3段で表示する。
- 参考回転率は、フィルタ適用後の完了セッションを `machineId` でグループ化して集計する。マップ描画時は `buildMachineStatsMap(filteredSessions())` を使い、計算量を O(セッション数 + 台数) に抑える。
- 参考回転率は累計加重平均（通常回転数合計 / 通常消費玉合計 * 250）。概算セッションを含む台は末尾に `≈` を付ける。
- 参考回転率の色分け閾値は `RATE_THRESHOLDS = { good: 17.0, bad: 15.0 }`。期待値対応プリセットかつサンプルありの場合のみ、17.0以上を緑、15.0未満を赤、15.0以上17.0未満を既定色で表示する。将来、設定画面化を検討する。
- 稼働中のセッションがある台には「稼働中」バッジを表示する。
- イベントフィルタ選択中は「絞り込み中」バッジと解除ボタンを表示する。該当セッションが0件の台は全期間値へフォールバックせず `-` を表示する。
- 台詳細ポップアップには、前回ヤメ回転数と日付、平均出玉、遊タイム玉減り平均を表示する。フィルタ適用中は、統計が絞り込み後の記録だけで計算されていることを明示する。
- Phase 3 は表示・集計ロジックのみの変更で、schema は 6 のまま。容量予算の増分はなし。
- 性能確認: ミコト環境の headless Chrome で 200台 / 1000セッションのマップ描画を確認し、タブ切替から最終台ボタン表示まで 1371ms。

## 5.7 P3追補 二重稼働の防止

- 同一店に `status: "active"` のセッションが存在する状態で別セッションを開始しようとした場合、開始前に確認ダイアログを表示する。
- ダイアログには「台○○がヤメ入力されていません。」と表示し、「台○○のヤメ入力へ」「そのまま新しく開始」「キャンセル」を選べる。
- 「台○○のヤメ入力へ」は稼働中画面へ移動し、既存activeセッションのヤメ入力を開く。
- 「そのまま新しく開始」を選んだ場合は旧activeを残すが、開始完了後は新しいactiveセッションを操作対象にする。
- `activeSession()` は、同店のactiveセッションを `updatedAt` / `createdAt` の新しい順で扱い、通常は最新activeを返す。画面上で切替済みの場合は選択中のactiveを優先する。
- 複数activeがある場合、稼働中画面の上部に「他に稼働中の記録があります」を表示し、台番ボタンで操作対象を切り替えられる。
- 引き継ぎ待機中でもactiveガードを優先して表示する。通常の引き継ぎは終了済みセッションから発生するため、実運用では競合しにくい。
- P3追補は画面状態と開始ガードのみの変更で、schema は 6 のまま。容量予算の増分はなし。

- Phase 4 期待値エンジンは v2 `yutime-record.html` の `YUTIME_RECORD_ENGINE` を式変更なしで移植し、v3 では `YUTIME_EXPECTATION_ENGINE` として `umi-sp5` プリセットに接続する。対象スペックは `hitProb: 1/319.6`、`tenjo: 950`、`yutimeJitan: 350`、`kakuhenRate: 0.54`、`jitanNormal: 100`、`jitanChain: 200`、既定 `netBallsPerWin: 1400`。

## 16. B11 閉店チェック連続入力モード

- schema は 12 のまま。B10の `dailyState` を流用し、保存データの追加は行わない。
- 閉店チェックON中に台番をタップすると、電卓型の連続入力モーダルを開く。端末キーボードは使わず、7〜9、4〜6、1〜3、C、0、⌫ の大ボタンで入力する。

## 17. B12 当たらずヤメの計算対応と差玉修正

- schema は 12 のまま。保存フィールドの追加は行わず、派生計算のみを変更する。
- 当たりなしセッションでは、通常回転数を `(hitSpin ?? endSpin) - startSpin` で算出する。これにより、ヤメ回転数と投入玉が入力済みの当たらずヤメも、戦果報告・台帳・参考回転率の累計に反映する。
- 遊タイム突入済みで当たりなしのセッションは、通常回転率を無理に `endSpin` まで伸ばさない。現行スキーマには遊タイム突入時点の回転数がないため、通常回転率への混入を避ける。
- タップ投入方式の差玉は `endTotalBalls - startMochidama - Σ(再プレ引き出し玉 + 現金の貸玉換算) + zanhoryuBalls` とする。持ち玉タップは開始持ち玉プール内の移動なので、差玉の投入側には数えない。
- 旧方式（source なしの投資レコード）は従来式 `endTotalBalls - totalInputBalls + zanhoryuBalls` を維持する。
- hitCount が 0 の当たりなし戦果報告では、当選時残り玉の概算と獲得出玉の概算は表示しない。

- 台メモは `Machine.memo` の単一フィールドを使う。マップにはメモ印、台詳細では朝一状態ボタン直下、稼働中パネルでは台名行のメモボタンから同じ内容を閲覧・編集する。
- セッション側の `memo` はヤメ時の記録メモであり、台メモ（釘・癖など）とは別物として扱う。
- B14 dailyState サンプル（当日hitToday＋前日closingSpin）: 124 chars

## 19. B15 入力プリセット総点検

- schema は 12 のまま。保存済みデータからウィザード初期値を作るだけで、保存フィールドは追加しない。
- 台詳細の期待値判定に入力した現在回転数は、打ち始めウィザードの開始回転数へプリセットする。未入力なら空欄のまま。
- carryover がない当日2台目以降は、同店の直近完了セッションの終了時点残高から、再プレ残とカード残をプリセットする。carryover がある場合は carryover を優先する。
- 同台の当日完了セッションに `endTotalHits` があれば、次回打ち始めの開始時累計大当たり回数へプリセットする。
- 当選入力の残り玉と、ヤメ入力の終了時玉数は、稼働中の持ち玉残をプリセットする。持ち玉残が未入力なら空欄のまま。
- 当たりなしヤメでは、ヤメ回転数に稼働中カウンタ `currentSpin` をプリセットする。当たりありでは時短消化でズレるためプリセットしない。
- すべてのプリセット値は編集可能で、ステップ説明に値の出所を表示する。

## 20. B16 機種名修正と左手操作レイアウト

- B15-1 の判定入力プリセットは、台詳細モーダルを閉じる前に現在回転数を読み取り、打ち始めウィザードへ渡す。

## 21. B17 判定の前日ヤメ手入力引き継ぎ

- schema は 12 のまま。保存フィールドは既存の `Session.prevDayEndSpin` を使う。
- 「この台を打つ」時、台詳細の期待値判定に入力した `evPrevSpin` をモーダル破棄前に読み取り、打ち始めセッションの `prevDayEndSpin` へ渡す。

## 22. B18/B19 当選後リセット、同台続行、計算修正

- schema は 12 のまま。カウンタリセットは既存の `currentSpin` を更新し、undo スタックは保存しない。同台続行は既存の `carriedFromSessionId` で連結する。
- 当選ウィザード完了後に「現在回転数をリセット」チップを表示する。`umi-sp5` は `0` / `jitanNormal` / `jitanChain`、プリセット外は `0` のみ。選ばず閉じた場合は変更しない。
- 当たりありで `hitSpin` が未入力の場合、通常回転数とセッション回転率は算出しない。当たりなしセッションのみ `endSpin - startSpin` を通常回転として使う。
- 通常回転数、通常消費玉、遊タイム玉減りが負に算出される場合は null とし、戦果報告に「入力を確認」注記を出す。保存値は変更しない。

- 戦果報告に「同じ台で続行」を追加する。開始回転数を `0` / `100` / `200` から選び、持ち玉、再プレ残、カード残、開始時累計大当たりを引き継いだ新activeセッションを即開始する。
- 稼働中パネルの残高表示は選択中ソースのみ表示する。統合投資ボタンは最頻操作として縦幅を拡大する。
