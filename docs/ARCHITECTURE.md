## 1. このサイトの目的

**パチンコ・パチスロの実戦を「打って終わり」にしない場所を作る。**

記録し、判断や結果を振り返り、検証することで、自分なりの立ち回りを改善していける環境をつくる。
さらに収支や数値だけでなく、その時の考えや感情も残すことで、過去の実戦そのものを振り返って
楽しめる場所にしていく。

期待値・設定判別・稼働記録・収支・検証・メンタル記録の各ツールは独立した商品ではなく、
この一連の体験を支えるための機能としてつなげていく。

### 体験の循環

```
打つ前に判断する → 打ちながら判断する → 記録する → 結果を見る
      ↑                                                  ↓
   立ち回りが変わる ← 振り返る・楽しむ ← 検証する・考える
```

### 「新しい楽しみ方」の位置づけ

半年前の自分の稼働を読み返して「この頃こんな狙い方をしていたのか」と気づけること。
これは目的そのものではなく、上の循環が回った**結果として生まれる価値**として扱う。
設計判断の根拠に使ってよいが、機能追加の理由を「楽しいから」だけに置かない。

## 2. やらないこと（歯止め）

目的と同じ重さで守る。迷ったらこちらを優先する。

1. **不正確なものは出さない。** 精度より誠実さ。根拠のない数値・推測での挙動記述を載せない
2. **店・台・他人を評価する道具にしない。**（反レビュー原則）
   星評価・店舗評価に転用できる構造を作らない。スタンプ語彙も同様
3. **勝ちを保証しない。** 断定的な期待値の約束や「勝てる」表現を使わない
4. **収支管理アプリ単体には寄せない。** 数字だけのツールなら既存サービスで足りる
5. **一次データを壊さない。** 実戦記録は不変。注釈・公開物は必ず別レイヤー
6. **有償解析値を出力物に載せない。**（§9-65）
7. **勝手に公開範囲を広げない。** 導線追加・サイトマップ登録は夢爽の明示承認が必要

## 3. 系統マップ

| 系統 | 体験上の位置 | ツール |
|---|---|---|
| 立ち回り系 | 打つ前の判断 | yutime-v3（遊タイム）、nerai |
| 判別系 | 打ちながらの判断 | 設定判別結果報告ツール（14機種） |
| 記録系 | 実戦中に書く | sf6-record（機種別）、rec4（機種非依存） |
| 振り返り系 | 後から読む・考える | kado-note（全機種共通ビューア）、log-2026 |
| 共通基盤 | 上を支える | 共通エンベロープ、共通店舗マスタ、解析更新自動検知 |

### 系統をまたぐ約束

- 判別系は「打ちながら」に閉じる。記録系のデータ構造とは接続しない（現状）
- 記録系と振り返り系は**必ず**共通エンベロープで接続する。ここが全体の背骨
- 立ち回り系と記録系は共通店舗マスタで接続する（移行作業中）

## 4. 共通基盤の約束事

### 4.1 記録→振り返りの二層構造

- **記録側**（sf6-record 等、機種別）＝実戦中に書く。一次データ
- **振り返り側**（kado-note、全機種共通）＝後から読む。スタンプを押す

接続は「共通エンベロープ（schemaVer 2）＋機種固有 payload」の2層JSON。
エンベロープが共通だから、ノート側は機種を知らなくても一覧とタイムラインを描ける。

### 4.2 sessionId は不変

セッション作成時に UUID v4 を一度だけ生成し、再保存・再エクスポート・ツール更新後も変更しない。
注釈レイヤーと将来の公開レイヤーがすべてこのIDで紐づくため、変わると振り返りが全て失われる。

### 4.3 注釈レイヤー（振り返りスタンプ）

一次データは書き換えず、`{sessionId, targetLogId, semanticId, stampId, t}` を別保存する。
語彙は設計側が管理する固定セット（初期24〜32個）。矢印の向きは「出来事」と「自分」に限定し、
店・台・他人に向く語彙は作らない。意味ID（semanticId）と絵柄ID（stampId）は分離する。

### 4.4 公開レイヤー原則

保存データは常に完全体。公開・共有物は明示的に選んだ項目だけを抜き出した別データ。
デフォルトは全項目非公開。公開フラグをエンベロープに混ぜない。

### 4.5 共通店舗マスタ

`slot-tools-stores-v1` を全ツール共通の正本とする。ID形式は yutime-v3 互換。
